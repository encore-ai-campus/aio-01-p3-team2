# 격리 복구 시연 결과 표시

`frontend-web/src/fault-lab-topology.js`의 결과 카드에는 `Auto Healing` 제목과 시험 실행 상태를 표시한다. 결과 제목은 Workflow의 실제 최종 상태를 사용한다. `SAFE_STOP`은 `안전 종료`, 오류 복구 후 승인 대기까지 진행한 결과는 `복구 완료`로 표시한다. 시험의 `PASS`/`FAIL`은 별도의 `5. 시험 판정` 항목에 표시한다. 안전 종료도 기대 정책과 일치하면 `PASS`일 수 있다.

결정적 시연 결과는 주입한 오류, 검출 결과, 정책 결정, 최종 상태, 시험 판정의 다섯 항목을 유지한다. 정책 결정과 최종 상태 사이의 `대응 전후`에는 `recovery_comparison` 근거를 표시한다.

- 기획안 재작성: 실제 Planner의 수정 전후 `summary`와 Critic 수정 이유를 표시한다. 요약은 `agent.recovery_resolved` Trace의 `PLAN_REVISION` 근거에서 가져온다.
- 재시도와 대체 조회: 원문 기획안이 변경된 것처럼 표시하지 않고, 오류가 난 시도와 복구 후 진행 상태를 비교한다.
- 저장 결과 재조정: 확인 응답 불명과 저장 결과 조회를 비교하며 쓰기 재실행으로 표현하지 않는다.
- 안전 종료 또는 내용 변경 없음: `기획안 변경 없음`을 표시한다. 이전 시연 기록에 비교 근거가 없으면 이를 알리고 원본 Trace 조회를 안내한다.

격리 시연 결과의 비교 데이터는 `backend/tests/support/fault_lab_runner.py`에서 조립한다. 실제 실행의 원본 Trace와 검증 항목은 기존 JSON 보고서에 유지된다.
