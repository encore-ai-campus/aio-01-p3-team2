# 격리 복구 시연 결과 표시

## 실행 경로 동기화 패치 통합

`8ea5c63`의 복구 전후 비교·사용자 Brief 시연 기능을 실행 경로 패치와 통합했다. 복구 사건은 공통 `append_recovery_event`로 발생 시점에 한 번 기록하고, 결과에는 `execution_path`와 `recovery_comparison`을 함께 제공한다. 사용자 Brief 시험은 기존대로 `workflow`도 반환한다.

신규 저장 완료 사건은 `storage.result_persisted` 하나로 기록한다. 과거 `planning.record_persisted`는 노드 대응과 화면 문구에서 읽기 호환성을 유지한다. 신규 정상 경로는 최종 검증 → 결과 쓰기 성공 → Supervisor 상태 전이 → 운영자 승인 대기이며, 최종 Trace의 사건을 화면 순서에 맞춰 재배치하지 않는다. 일반 기획 화면과 격리 복구 시연 화면 모두 저장 사건을 표시한다. 승인 대기는 저장과 같은 트랜잭션에서 커밋된 뒤 공개된다.

LAN HTTP 접속에서는 공유 `requestId()`를 사용하고, 클라이언트 요청 동일성 키는 Web Crypto digest가 없는 경우 JSON 표현을 사용한다. 서버의 요청 해시 검증은 유지한다.

`frontend-web/src/fault-lab-topology.js`의 결과 카드에는 `Auto Healing` 제목과 시험 실행 상태를 표시한다. 결과 제목은 Workflow의 실제 최종 상태를 사용한다. `SAFE_STOP`은 `안전 종료`, 오류 복구 후 승인 대기까지 진행한 결과는 `복구 완료`로 표시한다. 시험의 `PASS`/`FAIL`은 별도의 `5. 시험 판정` 항목에 표시한다. 안전 종료도 기대 정책과 일치하면 `PASS`일 수 있다.

결정적 시연 결과는 주입한 오류, 검출 결과, 정책 결정, 최종 상태, 시험 판정의 다섯 항목을 유지한다. 정책 결정과 최종 상태 사이의 `대응 전후`에는 `recovery_comparison` 근거를 표시한다.

- 기획안 재작성: 실제 Planner의 수정 전후 `summary`와 Critic 수정 이유를 표시한다. 요약은 `agent.recovery_resolved` Trace의 `PLAN_REVISION` 근거에서 가져온다.
- 재시도와 대체 조회: 원문 기획안이 변경된 것처럼 표시하지 않고, 오류가 난 시도와 복구 후 진행 상태를 비교한다.
- 저장 결과 재조정: 확인 응답 불명과 저장 결과 조회를 비교하며 쓰기 재실행으로 표현하지 않는다.
- 안전 종료 또는 내용 변경 없음: `기획안 변경 없음`을 표시한다. 이전 시연 기록에 비교 근거가 없으면 이를 알리고 원본 Trace 조회를 안내한다.

격리 시연 결과의 비교 데이터는 `backend/tests/support/fault_lab_runner.py`에서 조립한다. 실제 실행의 원본 Trace와 검증 항목은 기존 JSON 보고서에 유지된다.

## 일반 기획안 실행

`기획안 만들기`에서 제출한 Workflow는 `frontend-web/src/main.js`의 진행 기록 화면으로 이동한다. 이 화면의 `Auto Healing` 카드는 일반 Workflow의 실제 Trace와 상태를 사용한다. 복구 결정이 없으면 `정상 실행 · 복구 없음`, 복구 후 기획 흐름을 완료하면 `복구 완료 · 기획 정상 완료`, 안전 종료하면 `안전 종료`로 표시한다. 승인 대기는 `기획안 생성 완료 · 승인 대기`로 표현해 기획 단계가 끝났고 사람 승인이 남았음을 구분한다. 기획안 재작성 Trace에 수정 전후 Planner 설명이 있으면 비교하고, 재시도·대체 조회는 원본 기획안이 수정된 것처럼 표시하지 않는다. 일반 실행에는 격리 시연의 `PASS`/`FAIL` 시험 판정이 없다. 복구 결정과 완료는 발생 시점에 관측 Trace로 저장해 그래프의 시간 순서를 유지한다.

데모 로그인 뒤에는 최근 일반 Workflow를 다시 조회한다. 사용자가 새 기획안을 입력하기 전이면 진행 기록으로 이동하고, 이미 입력 중이면 화면 이동 없이 최근 기록만 선택해 둔다. 이전 Workflow를 보고 있었다면 `운영 로그`에서 원하는 기록을 다시 선택할 수 있다.

로컬 전용 Edge 검토 환경에서는 `pwsh -NoProfile -File infra/start-edge-review.ps1 -DemoRecoveryOnce`로 시작할 수 있다. 이 옵션은 전용 테스트 DB `eventquest_test`와 결정적 Planner를 사용하는 일반 API에만 `EVENTQUEST_LOCAL_DEMO_HEAL_ONCE=1`을 설정한다. 같은 DB를 사용하는 팀 로컬 서버는 해당 환경변수를 직접 설정하고 재시작해도 된다. 이 상태에서 `일반 기획안 실행`으로 새 기획안을 만들면 첫 Planner 출력의 미션 설명 목록을 한 번 누락한다. 기존 출력 계약 검사에서 `ERR-CONTRACT-PLANNER-001`을 검출하고 Supervisor가 현재 복구 정책에 따라 재시도한다. 두 번째 Planner 호출은 정상 출력으로 진행한다. 진행 기록에는 `시연용 Planner 응답 오류 주입`, 복구 결정, 복구 완료가 남으며 Auto Healing 카드에 주입 사실과 대응 전후를 표시한다. 사용자가 입력한 Brief는 수정하지 않는다. 이 오류는 자연 발생 오류가 아닌 로컬 시연 주입이다.

일반 API를 다른 방식으로 실행할 때 이 환경변수를 설정하지 않으면 기존처럼 실제 오류가 발생한 경우에만 복구 기록이 나타난다. `FAULT_LAB_MODE=isolated` 또는 결정적 Planner가 아닌 환경에서는 주입하지 않는다. 기존 Edge 검토 환경은 `infra/stop-edge-review.ps1`로 종료한 후 옵션을 넣어 다시 시작한다.

## 기획안 만들기에서 시작하는 복구 시험

`기획안 만들기`의 입력 폼에는 실행 방식 선택만 둔다. `일반 기획안 실행`은 기존 API로 제출한다. `시험: Planner 오류 1회 후 재시도` 또는 `시험: 검수 오류 1회 후 기획안 수정`을 고르고 기존 `기획안 검증 시작`을 누르면 입력한 기획안을 `brief`로 격리 시험 API(`/api/test/fault-runs`)에 보낸다. 각 방식은 `planner_output_invalid`, `planner_explanation_mismatch`를 첫 호출에 한 번 주입하고 `retry_allowed` 시험 정책으로 실행한다.

제출 후 `진행 기록`으로 이동한다. 완료 전에는 격리 시험의 상태를 표시하고, 완료 후에는 실제 Workflow Trace의 Auto Healing 카드와 그래프, 생성된 기획안 요약, 별도 시험 판정을 표시한다. 격리 실행에는 승인·게임 등록 동작을 제공하지 않는다. 시험 백엔드가 연결되지 않으면 폼에 연결 안내를 표시하고 일반 API로 우회하지 않는다. 일반 실행에서는 실제 오류가 발생한 경우에만 복구 기록이 나타난다.

격리 시험 요청의 `brief`는 선택 입력이며 `EventBriefInput` 계약을 따른다. `brief`가 없으면 기존 고정 샘플을 유지한다. 사용자 입력 `brief`는 위 두 시나리오에서만 허용하며, 격리 runner의 원본 요청 보존 검증도 해당 `brief`를 기준으로 수행한다. 완료 결과의 `workflow`는 기획 화면에서 시작한 시험에만 포함한다.

`reward_selection=planner`인 입력은 처음에 보상과 연결이 비어 있고 Planner가 실행 중 이를 제안한다. 이 경우 원본 보상 목록과 결과를 동일하게 비교하지 않으며, 생성된 보상에 연결이 빠지지 않았는지 확인한다. 명시 보상 입력의 기존 보상·연결 보존 검증은 유지한다.
