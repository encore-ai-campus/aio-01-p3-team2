# 운영 프론트엔드 기획안 결과 표시

대상: `frontend-web`, 2026-10-12.

결과 카드는 **생성된 이벤트 기획안**을 제목으로 표시하며 다음 순서로 읽는다.

1. 기획안 결과: 결과 버전과 실제 검토/승인 상태 배지
2. 기획안 요약: 반환된 `plan.objective`, 대상 유저, 운영 방식, 운영 기간, 이벤트 유형
3. 기획안 상세 내용: 콘텐츠별 미션 목표와 연결된 보상, 지급 조건, 지원 확인이 필요한 항목
4. 검토 결과 및 보완 사항: Runtime 지원 여부, 영향 평가 상태, 개발 요구와 검증 항목, 승인·수정 요청·거절·게임 등록 동작
5. 상세 근거: **근거와 진행 Trace 보기** 버튼으로 운영 로그의 선택한 TRACE 기록에 이동하고, 아래에서 데이터 기준과 영향 근거를 펼쳐서 확인

별도의 이벤트 이름이나 서술형 요약을 생성하지 않는다. 기획 목표는 결과 데이터의 문장을 사용하며, 누락된 대상·기간은 정보 없음/미정으로 표시한다. `ongoing`은 상시 운영으로 표시한다. 콘텐츠와 보상 이름은 기존 게임 카탈로그를 사용하고, 찾지 못하면 응답의 ID를 표시한다.

미션 목표는 응답의 행동·목표값·비교 조건을, 보상 지급 조건은 `grant_policy`와 `max_grants_per_user`를 사용한다. 보상의 지원 상태가 추가 개발·데이터 확인·정책 제한이면 해당 보상 옆에도 표시한다. 생성 완료와 게임 적용 가능 여부는 구분한다.

오류 시연 결과 카드는 이 기획서 레이아웃의 대상이 아니다.

# 수정 요청 흐름

기획안 검토 영역의 **승인** 버튼은 승인 결정을 저장한다. **수정 요청**을 누르면 최대 500자의 수정 의견을 입력할 수 있다. 제출 시 `POST /api/v1/decisions`에 `action: REQUEST_REVISION`과 `approval_comment`를 보내며, 서버는 의견을 보존하고 같은 기획안의 다음 버전을 만든다. 새 버전은 Planner 작성, 게임 카탈로그·규칙 검증, Critic 검토를 다시 거쳐 화면에 표시된다. 이전 버전과 의견은 진행 기록에 남고, 이전 버전에서 수정된 기획안으로 이동할 수 있다.

수정 의견은 Brief의 선호 조건으로 전달된다. 기존 퀘스트 목표, 대상, 기간, 도전 구간은 이 경로에서 자동 변경하지 않는다. Planner가 보상을 선택하는 기획안에서는 카탈로그 내 보상 재제안에 반영하며, 최종 적용 전 승인과 Runtime 등록은 별도 단계다.

승인된 기획안의 **가상 게임에 퀘스트 등록** 버튼은 `/api/game/events/apply`로 등록한 뒤 성공하면 새 창에서 로컬 데모게임 `http://127.0.0.1:5173/`을 연다. 브라우저 팝업이 차단되면 등록 전에 중단하고 안내한다. 등록이 실패하면 열린 빈 창을 닫는다. Trace 복구용 보조 버튼은 게임 창을 열지 않는다.
