# 코드 영역 분류 및 유지 기준

2026-10-13 현행 통합·CI/CD·OIDC 기준은 `main`이다. 기존 `ikonly` source의 시험은 당시 증거로 보존한다. [main 전환·실행 결과](ik/검증산출물/2026-10-13_main_CICD_전환과_병합.md).

기준일: 2026-10-13
기준 브랜치: `ikonly`

이 문서는 저장소 코드의 역할을 제품 실행 경로와 보조·과거 경로로 구분해, 현재 수정 기준과 보존 이유를 찾도록 돕는다. 분류는 정적 참조, 실행·배포 설정, 저장소 문서에 근거한다. 동적 플러그인이나 저장소 외부 실행은 정적 조사만으로 배제할 수 없으므로, 근거가 부족한 코드는 미사용으로 단정하지 않고 `확인 필요`로 둔다.

## 분류 기준

| 분류 | 판정 기준 |
|---|---|
| 현행 제품 | `ikonly` 기준 앱 진입점, 배포 이미지 또는 제품 요청 흐름에서 사용한다. |
| 보조·검증 | 운영·복구·시험·평가·초기화 등 한정된 목적으로 호출하거나 실행한다. 일반 사용자 요청 흐름과 구분한다. |
| 개발 중단·미사용 | 현행 제품 경로와 유지 중인 별도 실행 경로 모두에서 사용하지 않는다는 근거가 있고, 담당자가 중단을 확인했다. |
| 확인 필요 | 참조가 없거나 별도 브랜치·환경의 사용 여부를 알 수 없어 결론을 보류한다. |
| 보존 자료 | 현재 실행 대상이 아닌 초기 설계·마이그레이션·참고 자료로, 역사·추적 목적으로 유지한다. |

## Streamlit 경로 상태

Streamlit 코드는 `ikonly` 제품의 현행 UI가 아니다. 현행 UI는 `frontend-web/`이고 게임 화면은 `demo-game/`이다. Streamlit 파일 및 과거 배포 정의는 삭제하지 않고 GitHub Actions의 **Yejin Frontend Deploy** workflow 실행을 `disabled_manually`로 비활성화했다. 확인 시점에 진행 중인 실행은 없었다. 이 조치는 워크플로 파일·실행 이력을 보존하며, 다시 사용하려면 저장소 설정에서 workflow를 명시적으로 재활성화해야 한다.

main 통합 후 `frontend-infrastructure.yml`은 GitHub에 등록됐으며, 과거 Streamlit 경로가 현행 운영 경로로 사용되지 않도록 비활성화했다. 두 Yejin workflow는 `disabled_manually`로 보존한다. 기존 자원 부재 검사는 당시 계정·서울 리전 기준이며 다른 계정·리전에 대한 정리 완료를 뜻하지 않는다.

## 미사용 판정 기록 규칙

개발 중단 또는 미사용으로 확정할 때 아래 항목을 이 표나 후속 변경 기록에 남긴다.

1. 대상 경로와 판정 기준 브랜치·환경
2. 마지막으로 사용한 목적과 중단 이유
3. 현재 대체 경로와 대체 완료 근거
4. 코드·데이터·배포 설정을 보존하는 이유와 담당자
5. 재활성화 또는 삭제 조건, 외부 인프라 정리 여부

호출처를 찾지 못했다는 사실만으로 미사용 확정이나 삭제를 하지 않는다. 실행 설정, 수동 운영 절차, 별도 브랜치 및 외부 시스템의 참조를 확인한다.
