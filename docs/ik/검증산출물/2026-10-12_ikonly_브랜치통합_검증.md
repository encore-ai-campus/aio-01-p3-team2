# ikonly 분기 변경 통합 및 검증

## 1. 통합 범위

- 통합 전 `ikonly`: `0b3adc3`.
- 최신 원격 조회 후 `origin/ik_yejin_front`의 `8569e3d`와 이를 포함하는 `fix/recovery-ui-sync`의 `45e9e11`을 확인했다. 공통 분기점은 `d590517`이다.
- `fix/recovery-ui-sync`를 병합하여 변경된 기획안 화면·로그인 연출·결과 문서·수정 요청·복구 실행 경로 표현을 함께 반영했다. checkpoint/yejin 계열의 다른 변경은 통합 대상에 넣지 않았다.
- 하드코딩된 `http://127.0.0.1:5173/` 게임 자동 이동은 제외했다. 승인 후 실제 게임 등록 API와 저장된 결과 확인은 유지한다.
- 새 UI의 개별 오류 선택·실행과 결과 경로 표현을 유지하되 입력 형식/보안 검사 두 시나리오를 복원했다. 오류 코드와 실행 가능한 기본 시나리오는 모두 28개다. 카탈로그 버전은 `fault-lab-v1.4`다.

## 2. 4번 점검: 수정 요청과 상태 관리

| 확인한 문제 | 통합 시 보완 |
| --- | --- |
| 수정 요청 상태가 Supervisor 상태 밖에서 덧씌워짐 | Supervisor가 `approval_revision_requested`를 받아 `REVISION_REQUESTED`로 전이한다. 조회와 polling도 동일 상태를 따른다. |
| 자식 기획안·부모 결정·Trace 저장이 일부만 성공할 수 있음 | 한 DB 트랜잭션으로 저장하고 부모 행을 잠근다. 실패하면 함께 롤백한다. 메모리 경로도 스냅샷을 복원한다. |
| 기존 PostgreSQL 제약이 수정 요청을 거부함 | `018_canonical_plan_revision.sql`로 결정 action에 `REQUEST_REVISION`을 허용한다. 기존 행은 보존한다. |
| V2 게임 등록이 task ID만으로 V1 상태를 갱신함 | 정확한 `task_id + result_version`의 Workflow에 등록 전이와 Trace를 기록한다. 게임의 소스 미리보기도 최신 승인 버전을 반환한다. |
| 새 UI의 거절 버튼이 거절 전이를 지원하지 않는 결과에도 표시됨 | 거절은 `WAITING_APPROVAL`에서 표시한다. 검토/개발 필요 결과의 수정 요청은 유지한다. |

수정된 기획안은 동일 task/plan의 다음 버전으로 생성되고 별도 Workflow에서 다시 검증·승인한다. 부모의 승인은 자식에게 승계되지 않는다. 동일 멱등성 키의 수정 재요청은 기존 자식을 반환하며 다시 생성하지 않는다. 승인된 버전의 수정 요청은 거절한다.

| Edge 진행 그래프 정상/검토/차단/복구/안전 종료/승인/거절/등록/재조회 | 13 PASS |

전체 오류 실행은 별도 PostgreSQL 시험 DB·MCP·시험 Backend와 실제 검출/정책/복구 코드를 사용했다. LLM 응답은 결정적 어댑터를 사용했으며 유료 OpenAI 호출, 복합 오류, 과거 137개 정책 조합 전부의 재실행을 의미하지 않는다. 과거 보고서는 보존한다. v1.4로 새 정밀 시험을 진행할 때는 해당 버전으로 시험 명세를 다시 생성한다.

최종 일반 UI 연결 검증은 **16 PASS / 2 SKIP**다. 기본 화면 계약·선택 공간/자동 보상·승인/등록·Trace 실패 재시도·보안 차단·정책 활성화/롤백·비동기 연결을 확인했다. V2 수정→재승인→게임 등록→저장된 보상/버전/소스 조회는 Edge에서도 **1 PASS**다. Ruff check/format 검사, 테스트 함수 등록 대조와 Vite production build를 통과했다. 별도 MCP 503 서버와 Backend 재시작 설정이 필요한 두 검사는 기본 실행에서 제외되며 테스트 파일과 CI 단계는 유지한다.

## 4. 배포와 문서

이번 작업은 로컬 통합이다. 기존 AWS 배포 성공 증거는 당시 버전에 대한 기록이며 이번 UI 버전의 AWS 배포를 증명하지 않는다. 실제 AWS 자원을 생성하거나 업데이트하지 않았다.

기존 DB로 실행/배포할 때는 018 migration을 먼저 적용해야 한다. 로컬 준비 script의 migration 목록과 운영 migration 검색에 포함된다. SQL/공유 계약 변경이므로 배포 영향 검토와 이미지 검증 게이트를 따른다.

문서 입구는 [README](../README.md), 현재 상태는 [현재 구현 상태](../현재_구현상태.md), 시험 화면의 현재 계약은 [오류시험실 §14](../기획안설계/16_오류시험실_구현과_검증.md#14-2026-10-12-ikonly-통합-기준)다. `pre/` 보존 문서는 변경하지 않았다.
