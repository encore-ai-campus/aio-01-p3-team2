## 배포 계약

- main의 성공한 전체 CI images/verified artifact를 재사용한다. 문서만 변경된 no-op run을 이미지 공급원으로 사용하지 않는다.
- AWS 계정·서울 리전·환경 `ikonly-demo`·수동 종료·현재 PC /32 접근·6개 EC2/private RDS 구성은 기존 합의를 유지한다.
- backend/.env와 승인 정책을 로컬에서 임시 SecureString으로 공급하고 Actions initial이 생성·배포·연결 수용을 실행한다. 증거 개인키와 복호화 원본은 Git 제외 로컬에 보존한다.
- 자동 업데이트는 main, 첫 배포와 초기화는 명시적 lifecycle 작업이다. 배포 후 앱을 자동 초기화하지 않는다.

## 시도 1: 배포 전 차단과 보완

[initial 38341519452](https://github.com/ik-e/multi-agent-autohealing/actions/runs/38341519452)는 OIDC 인증과 키 공급 claim 이후 CI source 대조에서 차단됐다. 성공 CI source `939472c`와 실행 source `aed8a41`의 차이는 문서였으나, gate가 `docs/`만 허용해 루트 README.md 변경을 실행 코드 차이로 취급했다. AWS 생성 단계는 SKIPPED였고 활성 앱 stack은 없었다. always cleanup 결과 SUPPLY_REMOVED / remaining_count=0을 확인했다.

gate는 `docs/`와 정확한 루트 `README.md`만 source 차이로 허용하도록 보완했다. 임의 Markdown·실행 코드·workflow 변경은 허용하지 않는다. 실제 YAML 내 Python 조건식을 검사하는 회귀 사례로 README/docs 허용과 Backend/workflow/deploy 코드 거절을 확인했다. 오류 메시지도 main으로 맞췄다.

로컬 영향 시험 8 PASS, Ruff check/format 통과. 추가 검사의 초기 AST 선택 오류를 바로잡은 뒤 통과했으며, 실패한 로컬 검사도 최종 성공에 섞어 집계하지 않는다. 이번 검사 함수 안의 상황을 보충했으므로 전체 시험 건수는 늘지 않는다.
