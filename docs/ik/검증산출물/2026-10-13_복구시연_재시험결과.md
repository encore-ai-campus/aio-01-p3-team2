## 5. 과정·증거·재현

첫 export는 저장 요청의 `brief: null`과 이전 명세의 생략 표현 때문에 매칭을 거절했다. 완료된 기본 28개는 재사용하고 요청 기본값만 정규화해 독립 대조했다. 기대값을 수정하거나 과거 실패를 재작성하지 않았다. 브라우저 준비의 작업 디렉터리 상대 경로와 JSON reporter의 중첩 출력 경로도 맞춰 증거를 확보했다. 이 준비/증빙 문제들은 앱 장애 case에 집계하지 않는다.

로컬 원본:

- `backend/test-results/recovery-retest-2026-10-13/`: campaign.py, 실행 전 manifest/baseline, run-ids, 묶음 원본·독립 대조, evidence.json(137개 case별 기대/실제/checks/시간), final.json 및 post-ui-final.json.
- `backend/test-results/fault-lab/<run ID>.*`: runner journal·결과. 시험 DB에도 저장한다.
- `frontend-web/test-results/recovery-retest-2026-10-13/`: 기존 시험 파일을 실행하는 별도 config, 네 Playwright JSON, actual-report.json, animation-observations.json, desktop/mobile 스크린샷.

GET `/api/test/fault-suites/<실행 ID>`로 재조회한다. 재실행은 CLEAN에서 이번 명세의 request를 네 묶음으로 순차 POST하며 새 멱등 키를 사용한다. 기존 prepare_fault_precision CLI의 preflight는 과거 카탈로그/5183 기준이므로 별도 로컬 runner로 이번 카탈로그·정책·요청·digest를 확인했다. 독립 export 판정 함수는 기존 것을 사용했다.

## 6. 종료 상태와 제한

UI 추가 실행 종료 후 **CLEAN**, 시험 정책 version/hash 원복, 시험 게임 데이터 불변, 일반 정책 167 불변, 앱 source digest 불변을 확인했다. 사용자 게임에 이벤트 승인·등록·보상 지급을 하지 않았다. runner와 Edge 검사 프로세스는 종료됐으며 사용자용 DB/MCP/일반·시험 Backend/두 프론트 서버는 유지한다.

복합 오류, 실제 DB 프로세스 중지, 실제 provider 장애·품질·토큰 비용, AWS 배포·파이프라인 장애는 다시 시험하지 않았다. [과거 실제 LLM 결과](2026-10-11_실제LLM_복구추가시험결과.md)와 [AWS 수명주기 증거](2026-10-12_AWS_배포수명주기_구현검증.md)는 환경·코드 버전을 구분해 참조한다. 이번 로컬 결과만으로 가이드 전체 배포·알림·CI/CD 검증 완료를 주장하지 않는다.
