# main 병합 전 문서·코드 전체 점검

기준일: 2026-10-13 (Asia/Seoul). 점검 HEAD: `a766f70`, 브랜치 `ikonly`. 이번 작업은 검사와 결과 기록이며 병합·push·코드 수정·AWS 생성은 수행하지 않았다.

## 1. 결론

**현재 커밋의 코드는 마지막 성공 Linux CI와 같고 이번 로컬 회귀 검사도 통과했다. Git 이력상 main에 충돌 없이 통합할 수 있다. 다만 main에서 CI/CD까지 이어지는 구성은 아니며, 문서 작업 트리도 정리되지 않았다.**

소스 보관을 위한 병합과 main을 새 배포 기준으로 삼는 전환은 다른 작업이다. 현재 배포 기준을 유지하면 main 병합 후에도 AWS 자동 업데이트는 ikonly에서만 실행된다.

## 4. main 전환 시 주의할 CI/CD

| 발견 사항 | 의미 |
|---|---|
| `ikonly-ci.yml` push branches와 job/ref 검사가 ikonly에 고정 | main push에는 현재 CI가 자동 실행되지 않음. main에서 수동 실행해도 ref 검사가 차단 |
| `ikonly-lifecycle.yml` job과 CI head_branch 검사 | main에서 첫 배포/정리 실행 불가 |
| `publish_release.py` ref·head_branch 검사 | main의 실행/증거를 현재 배포 경로가 수용하지 않음 |
| `bootstrap_oidc.py` trust subject | 권장 생성 subject는 refs/heads/ikonly. main 배포 전환에는 IAM trust 확인·변경 필요 |
| GitHub main 보호 없음 | main의 필수 상태 검사·직접 push 제한이 설정되어 있다고 가정하면 안 됨 |
| 과거 Yejin workflow 파일 보존 | Frontend Deploy는 API 조회상 disabled_manually. main 병합으로 과거 파일을 현행 배포 경로로 해석하지 않음 |

따라서 코드 변경 없이 병합할 경우 **main은 통합 소스, ikonly는 현재 CI/CD 실행 기준**이라고 문서에서 구분해야 한다. main을 실행 기준으로 바꾸려면 workflow trigger·검증 ref·run source·OIDC trust 및 영향 시험을 함께 전환해야 하며, branches 목록만 바꾸는 것으로 끝나지 않는다. 이번 요청에서는 변경하지 않았다.

## 6. 병합 전 권장 순서

1. 미커밋 문서 변경의 최종 포함 범위를 팀장이 확인하고, IK 경계·최신 기록 우선순위·절 링크를 정리한다.
2. main이 통합 소스만 담당할지 CI/CD까지 이어받을지 확정한다. 후자라면 위 브랜치·OIDC 전환이 선행되어야 한다.
3. 포함할 변경만 커밋하고 최신 로컬 문서 커밋도 원격에 반영한다. GitHub에서 병합할 경우 원격 SHA를 확인한다.
4. 팀장이 최신 origin/main 기준으로 통합한다. 배포 ref를 바꾸지 않으면 ikonly 및 현재 OIDC 연결은 유지한다.

기능 회귀 실패는 발견하지 않았다. **남은 주요 판단은 미커밋 문서의 확정과 main의 CI/CD 책임**이며, 미검증 운영 한계를 문서만으로 완료 처리하지 않는다.
