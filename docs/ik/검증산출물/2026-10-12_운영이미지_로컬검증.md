## 이미지

아래는 로컬 image ID이며 ECR digest나 승격된 release가 아니다.

- `ikonly-application:a3`: `sha256:af85a3975cd9deb7e9cd243bef54153d169e7b904cb8e3ab0d23ec32baefd2f7`
- `ikonly-web:a3`: `sha256:222ca55b9663203b0f31337d7c742943323867d112739c9eeea306cc97117ce3`

두 이미지 모두 UID/GID 10001로 실행한다. application은 runtime 의존성을 hash로 고정하고 실제 시험 runner helper만 포함한다. web은 두 화면을 frozen install로 빌드한다. 환경 파일·비밀키·개발 venv·옛 UI·전체 시험 디렉터리는 포함하지 않는 것을 확인했다.

서울 RDS 공식 CA는 build에서 SHA256 `913fb5b814f17af79d4c1622584a8d0ceddf5b0d76fe353d0c7d1186cdd6b229`을 확인한다. 로컬 시험에서는 fixture의 자체 CA를 별도 mount했다.

## 실제 연결 검증 범위

main-api, fault-api, main-mcp, fault-mcp, plan-web, game-web의 여섯 역할을 실제 이미지로 실행했다. 임시 실제 PostgreSQL의 서로 다른 DB/role과 실제 MCP를 사용했다. main-api의 OpenAI 설정은 호출하지 않는 시험용 값이므로 실제 LLM 인증 성공을 의미하지 않는다. 유료 호출은 없었다.

- 필수 설정 누락 시 시작 거부, read-only root 및 capability 제거 상태에서 실행.
- HTTP에서 외부 HTTPS443으로 redirect, 미인증 401, 인증 후 HTML/JS와 게임 자산 제공.
- 잘못된 MCP Host 421·Origin 403, 직접 API 접근 403, 브라우저 proxy header 덮어쓰기.
- 일반/시험 API 분리, 게임 DB 조회, 게임 사이트 직접 `/api/*` 접근 404.
- 공유 maintenance에서 mutation 차단, owner 해제 후 정상화.
- `input_validation_error`, `input_guard_blocked`, `mcp_game_rules_error` 세 시험 모두 PASS.
- 시험 자식 process 실행·journal 기록 및 fault-api 재시작 후 기록 유지.
- fault-api 중단 시 시험 경로 502, 일반 API로 우회하지 않음.

입력 오류 시험은 실제 planning APIRoute와 validation handler를 in-process로 실행한다. 별도 공개 포트나 운영 ingress 우회 경로를 추가하지 않았다. 자식 실행의 DB guard와 snapshot 검사는 유지했다.

## 중간 실패와 해결

| 발견 | 해결·재검증 |
|---|---|
| Windows node_modules가 web context에 포함되어 Linux 의존성 덮어쓰기 | Docker ignore allowlist 수정. context 약 295.7MB → 34.69MB, 빌드 성공 |
| Caddy file capability와 cap_drop ALL 충돌 | 불필요한 capability 제거, high port 실행 성공 |
| read-only 실행 시 Caddy 내부 CA 저장 실패 | `/data`, `/config` 영구 volume 및 writable 검사 추가 |
| Windows stdin CRLF로 BasicAuth hash 변형 | Docker helper 입력을 UTF-8 bytes로 전송, 인증 통과 |
| 새 FastAPI lazy router 때문에 입력 오류 시험 INCONCLUSIVE | include 전에 실제 APIRoute 선택, 단위·실제 자식 시험 통과 |
| 자동 HTTPS redirect가 내부 8443을 사용할 가능성 | 명시적 외부 443 redirect, 실제 응답 header 검증 |
| inventory 처리에서 cp949 decode 실패 | UTF-8 명시, 모든 신규 시험 등록 |

실패 시험을 제외하지 않고 수정 후 위 최종 결과를 얻었다.

## 재현과 자원

```sh
docker build -f infra/aws/Dockerfile.application -t ikonly-application:a3 .
docker build -f infra/aws/Dockerfile.web -t ikonly-web:a3 .
backend/.venv/Scripts/python.exe -m pytest backend/tests/integration/test_production_images.py --test-profile postgres -q
```

이미지 시험에는 `CLOUD_IMAGE_TESTS=true`, `CLOUD_DATABASE_TESTS=true`와 명시적인 격리 `POSTGRES_TEST_URL`이 필요하다. 접속 비밀값은 문서·명령 예시에 기록하지 않는다. migration 시험은 격리된 `MIGRATION_TEST_URL`도 사용한다.

fixture 소유 label을 확인해 시험 container/volume/network와 임시 환경 파일을 정리했다. 남은 시험 container/network가 없음을 확인했다. 사용자 서버와 일반/시험 DB는 변경하지 않았다. 로컬 이미지와 build cache는 다음 CI 준비에 사용한다.

## 남은 수용 검증

A4에서 Linux CI·실제 이미지 browser E2E·source SHA와 artifact digest·release gate를 연결해야 한다. A5에서 인증 후 실제 private RDS·SG·IMDS·SSM·IAM·public ACME를 검증한다. A7 이후 실제 OpenAI 정상 호출, 배포·복원·정리 시험을 수행한다. 이 기록은 실제 AWS 배포 및 장애 복구 보고서의 완료 증빙이 아니다.
