# 현행 코드 CI/CD 마무리 검증

상태: **로컬 선행 검사 완료 / 원격 CI·OIDC·CD 검증 진행 전** · 2026-10-13

## 1. 기준과 작업 범위

[이전 배포 수명주기 수용](2026-10-12_AWS_배포수명주기_구현검증.md)과 [운영 가이드](../기획안설계/26_AWS_배포운영_실행가이드.md)를 기준으로, 통합된 기획안 UI·원자적 수정 요청·게임 계약·Critic 보완을 포함한 ikonly의 현재 source를 검증한다. 과거 성공 run을 현재 코드의 성공 증거로 사용하지 않는다.

현재 구조는 DB/실제 MCP/UI 및 production 이미지 검사 후 같은 CI run의 검증된 tar만 승격하고, OIDC로 활성 환경의 필요한 역할만 업데이트한다. 초기화된 환경의 update는 INACTIVE로 끝나며 새 유료 앱 자원을 생성하지 않는다. 첫 배포는 로컬 키 공급, 전체 초기화는 로컬 증거 보관을 사용하는 기존 계약을 유지한다.

## 2. 보완 사항

- Critic 중복 SCOPE REVIEW 보완 및 관련 단위 시험을 core에 등록했다. 복구 시연의 WAITING_REVIEW 표시 회귀도 기존 UI suite에서 검사한다.
- 원격 검사 준비 중 기본 CI가 fault-lab 화면 fixture를 선택하지 않는 것을 확인했다. `fault-display` phase에서 provider 표시·WAITING_REVIEW 표시 2건을 명시적으로 선택하고 JUnit/승인 gate에 포함한다. 실제 실호출/과거 저장 결과에 의존하는 opt-in 시험은 포함하지 않는다.
- 첫 선택 regex의 시작 anchor 때문에 Playwright의 파일명을 포함한 전체 제목과 맞지 않아 로컬 collect가 0건이었다. anchor를 제거한 뒤 collect 2건 및 Chromium 2/2 PASS를 확인했다. 로컬은 표시 fixture만 검증했고 연결 검증은 원격의 실제 시험 API 단계에서 수행한다. superseded CI 38307232340과 대기 run 38307439677은 취소했으며 최종 성공 증거로 사용하지 않는다.
- 기존 workflow 전체 concurrency가 브랜치당 단일 pending slot을 공유해 OIDC 점검 dispatch가 대기 중인 push 38307537069를 교체했다. pipeline/operations 대기열을 분리하고 회귀 검사를 추가했다. deploy와 operations는 기존 `ikonly-demo-lifecycle` 잠금을 공유하므로 실제 AWS 변경은 직렬화한다. 취소된 run을 통과나 현재 source의 이미지 증거로 사용하지 않는다.
- run 38307685039에서는 fault-display 2건이 FAIL했다. 복구 시연은 격리 API 상태·catalog가 있어야 결과를 그리는데, 기존 표시 fixture는 결과만 대체하고 상태/catalog는 로컬 8013 서버에 의존했다. CI에서 registry 기반 catalog와 명시적인 표시 전용 격리 상태를 대체하도록 보완했다. fixture가 없으면 이 phase는 즉시 실패한다. 연결·실제 복구는 별도 PostgreSQL/production 이미지 시험의 역할이며 표시 fixture를 실제 API/LLM 시험으로 집계하지 않는다. 보완한 독립 표시 시험은 로컬 Chromium 2/2 PASS다.
- 로컬 `backend/test-results/`와 루트 `.vite/`를 Git에서 제외했다. 원본은 디스크에 보존하며 키/개인 환경 파일·원문·임시 도구가 커밋에 섞이지 않도록 한다.
- `.gitignore` 변경은 CI를 실행하지만 서비스 교체나 DB migration을 요구하지 않는 repository-hygiene 규칙으로 분류했다. 미분류 runtime/IaC 검토 경계는 유지한다.
- 기능 보완은 `262cedc`, CI 로컬 증거 제외·변경 영향 보완은 `0e05eee`로 커밋했다. 문서·화면 증거는 별도 커밋한다.

## 3. 선행 확인

원격 production browser의 기존 제목 기대값도 보완했다. run 38307685039의 화면·Trace 원본에서 실제 결과는 `시험 COMPLETED · 복구 완료`, 승인 대기 및 PASS였으나 검사가 옛 `시험 COMPLETED · PASS` 제목을 기다렸다. 현재 제목을 읽고, 생성한 실행 ID의 저장 API를 별도로 조회하여 COMPLETED/PASS/WAITING_APPROVAL·재시도 발생·모든 독립 체크 통과 및 일반 정책 보존까지 확인하도록 강화했다. 로컬 실제 일반 API/격리 API에서 수정 검사 1 PASS를 확인했다. 이 로컬 수용은 production TLS 이미지 검증을 대체하지 않는다.

원격 실패 run 38307685039는 UI/이미지 검사 실패 → release-gate 실패 → deploy SKIPPED로 끝났다. 이는 실패한 후보를 배포하지 않는 실제 차단 증거다. 이후 중간 run 38308311118은 이 제목 보완 전 source라 취소하고 최종 수정 source를 다시 검증한다.

## 4. 원격 확인할 완료 기준

1. 이번 source의 quality-core/PostgreSQL/UI/build/verify-images/release-gate가 성공하고 같은 SHA/run/attempt의 증거와 이미지 지문이 일치한다.
2. 실패·누락·skip 필수 검사를 승인하지 않는 gate 계약을 유지한다.
3. 원격 deploy가 실제 OIDC로 인증하고 앱 상태를 조회한다. ABSENT이면 INACTIVE/created_resources=false를 확인한다. 이를 현재 코드의 AWS 서비스 배포 완료로 표현하지 않는다.
4. 기존 첫 배포·선택/전체 업데이트·rollback·reset 경로와 최신 성공 CI artifact 사용 방법을 운영 가이드에 연결한다.
5. 원격 run ID/URL·artifact·최종 상태를 기록하고 README/현재 상태와 동기화한다.

실제 완료 결과는 이 문서의 후속 절에 추가한다. AWS 앱을 다시 생성한 경우에는 배포 수용과 정리까지 별도 기록한다.
