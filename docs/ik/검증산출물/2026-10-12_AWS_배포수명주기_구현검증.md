# AWS 배포 수명주기 구현 검증

기준: [운영 가이드 26](../기획안설계/26_AWS_배포운영_실행가이드.md).

## 확인한 사실

- Ruff/format, Python compile 및 IaC/계약 생성 일치 검사를 수행했다.
- 실제 계정에서 `bootstrap_oidc --apply` 성공. 공유 provider 재사용, 두 제어 IAM 역할과 비밀값 없는 GitHub 변수를 생성했다. OIDC subject는 저장소 실제 immutable ID + ikonly ref다.
- 새 status 검사로 앱 환경 ABSENT 및 잔존 항목 부재를 조회했다. RDS 자동 로그 누락 보정은 [정리 결과](2026-10-12_AWS_정리결과.md)를 따른다.
- 현재 앱 서버·DB를 새로 생성하지 않았다. 인증 연결 생성과 앱 운영 수용 성공을 구분한다.

## 아직 확인할 항목

GitHub 실제 OIDC 세션, 원격 Linux CI, 새 경로 첫 배포/선택 업데이트/전체 업데이트/실패 rollback/초기화 재실행. DB snapshot 자동 복원은 구현 범위에 포함하지 않았다. 코드 구현만으로 이 항목을 성공으로 기록하지 않는다.

## 초기화 후 자동 CD 시험

[CI/CD 38218237440](https://github.com/ik-e/multi-agent-autohealing/actions/runs/38218237440) 전체 성공. deploy job은 실제 OIDC 인증 후 `INACTIVE`, `created_resources=false`를 기록했다. 앱을 재생성하지 않는 계약을 실제 확인했다.

최초 로컬 이미지 다운로드는 원격 TCP 종료로 실패했고, 첫 배포는 artifact 검증 전에 중단되어 유료 앱 자원을 만들지 않았다. `download_artifact.py`는 8MiB 범위 4개 동시 다운로드, 5회 제한 재시도, 로컬 범위 이어받기와 GitHub ZIP digest 검사를 제공한다. signed URL/토큰은 출력·저장하지 않는다.

## 새 경로 실제 첫 배포 시험 진행

로컬 첫 배포 시험을 시작했다. 검증된 CI ec454a4 artifact와 로컬 `.env`/기존 승인 정책을 사용하며 네트워크 및 IAM stack CREATE_COMPLETE를 확인했다. RDS 생성 이후 서비스 수용·복구·전체 초기화를 이어서 확인한다. 시험 진행 중 임시 앱 자원이 존재하며 종료 후 잔존 검사를 다시 기록한다. 이 시점의 생성 성공은 전체 시스템 수용 성공을 뜻하지 않는다.

## 첫 배포 실패 보정 및 보상 정리

EC2까지 CREATE_COMPLETE 후 관찰성 stack이 S3 `PutBucketOwnershipControls` 권한 누락으로 실패했다. 로컬 시험 자료를 저장하고 첫 배포의 빈 baseline/token 보호 조건에 따라 자동 reset이 역순 삭제에 진입했다. 제어 CFN 역할에 해당 버킷 namespace의 ownership/versioning read/write 권한을 보완했다. Access Analyzer 성공은 정책 문법 검사이며 서비스에 필요한 모든 권한의 존재를 보증하지 않는다는 점을 실제 시험으로 확인했다. OpenAI 키 공급·DB 초기화 전 실패이므로 LLM 호출은 발생하지 않았다. 자동 reset 완료/재시도 결과는 후속 기록을 따른다.

기존 data stack의 final snapshot 생성 대기를 확인했다. 사용자가 전체 삭제를 확정한 초기화에서는 신규 final snapshot을 바로 폐기하므로, 이후 신규 stack은 DeletionPolicy=Delete로 개선했다. 기존 삭제 중인 stack에는 적용하지 않았다. migration/replacement backup 보호는 유지한다.

초기화 정책 변경에 영향을 받는 기존 infrastructure 단위 검사 21개 통과(약 6초), Ruff/format·IaC 생성 일치 확인. DB 전체 삭제/교체 snapshot 보호/automated backup 삭제 계약 assertion을 갱신했다.

첫 배포 실패의 자동 reset 완료: `test-results/aws-lifecycle/initial/result.json=INITIAL_FAILED_AND_RESET`, 잔존 검사 전 항목 0. 제어 역할은 유지했다. S3 registry의 실제 read-handler permissions를 대조해 프로젝트 증거 버킷에 한정된 모델 읽기·태그 권한을 보완했다. API 명칭과 다른 IAM ownership 삭제 action은 제거했고 bootstrap apply 전에 Access Analyzer ERROR 차단을 추가했다. 재시도는 별도 `initial-retry1` 출력에 기록한다.

API/MCP private bind와 수용 검사 주소를 대조해 loopback 검사 주소를 실제 private IP로 보정했다. 기존 코디네이터를 정확한 작업 PID로 종료하고 종료 확인 후 원래 lock token을 해제했다. 아직 앱 state/키/초기 데이터가 없는 시점이라 원래 생성/검토 기록과 실제 리소스를 검증하여 `initial-resumed`에서 이어받았다. 네트워크·IAM·RDS·EC2를 재생성하지 않았고 master Parameter를 유지했다.

Private bind 검사 실행(API/MCP 각 port) 및 원래 소유 token/서비스 Parameter 유입 시 resume 차단 회귀 검사를 추가했다. infrastructure 관련 총 24 case PASS(약 1초), 테스트 분류 manifest에 두 함수를 반영했다. 역할별 readiness 검사에서 실제 private 주소 사용을 확인한다.

첫 배포의 내부 six-service 수용 후 실제 Basic 로그인에서 Windows stdin CRLF로 비밀번호에 CR이 포함된 문제를 확인했다(원문 비밀번호 401, CR 추가 비밀번호 200). 명령 stdin을 bytes로 바꾸고 두 웹의 SecureString hash를 갱신·동일 accepted 이미지에 재적용했다. 이후 first-deploy 성공 게이트에 실제 공개 HTTPS 인증/조회 callback을 추가해 이 문제를 초기 성공 전에 검출한다.

공개 HTTPS/실제 Basic 인증으로 두 화면·게임 상태·시험 catalog 조회 PASS. 실제 성장 POST 후 사용자 attack=15를 기록했다. 실제 CI 이미지 six-service 교체 후 마지막 game-web SSM 성공 지점에서 코디네이터 예외를 1회 주입했다. 자동 rollback 결과 ROLLED_BACK/ACTIVE, accepted baseline 그대로, 게임 user 데이터 전체 동일을 확인했다. 시험은 실제 DB/SSM/이미지를 사용하며 원격 코드를 대체하지 않았다. 근거: `recovery-trial/trial-result.json`, `game-persistence.json`.

선택 업데이트 실제 수용: `selective-game-web/result.json=ACCEPTED`, targets game-web 1개. plan-web/main/fault API/MCP 5개 service 객체(source/digest/deployment ID) 완전히 동일, global maintenance=false. 사용자 상태 보존 및 선택/의존성/Windows stdin 회귀 포함 관련 unit 26 case PASS. 새 fixture의 default version 누락 assertion을 보정했고 원격 실패 CI의 deploy 차단을 유지했다. GitHub 전체 업데이트는 [수동 승인 run 38233956964](https://github.com/ik-e/multi-agent-autohealing/actions/runs/38233956964)에서 실행 중이다.

경로는 모두 로컬 `test-results/aws-lifecycle/` 아래다. 원시 로그/저널/공개 CA/개인 로그인 파일은 로컬에만 보관하고 커밋하지 않는다. 제어 IAM 역할 `ikonly-control-controller`, `ikonly-control-cloudformation` 두 개와 공유 OIDC provider를 유지했다. 앱 OpenAI Parameter·DB·이미지·로그·S3 보존 자원은 삭제했다. Windows 기존 인증서 제거는 보류 상태이며 새 CA는 신뢰 저장소에 추가하지 않았다.

추가 회귀로 reset의 RESETTING/원래 증거 directory/완료 quiesce guard를 검사해 종료된 host를 다시 접촉하는 재시도를 막았다. CI에서 default version을 빠뜨린 fixture assertion 실패를 수정했고 실패한 CI는 deploy가 차단됐다. 최종 source의 실제 remote full CI/배포는 위 run에서 성공했다.

### 검증의 한계

이번 수용은 이미지 교체 실패와 첫 생성 실패의 복구를 포함한다. DB migration 이후는 점검 유지·정확한 실패 source 재시도이며 snapshot을 자동 복원하지 않는다. 기존 로드맵 VG-A8의 별도 RDS snapshot 복원·원문 key 복호화 시험은 수행하지 않았다. 이 항목을 이번 시험 성공으로 표현하지 않는다. 첫 배포의 새 공개 인증 callback은 실제 두 화면/API 조회로 확인했고 미래 fresh deployment에는 accepted state 기록 전 실행한다.
