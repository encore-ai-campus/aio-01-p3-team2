# SSM 임시 공급 세대 관리 보완

2026-10-13. 사용자는 다른 세션의 최신 분석에서 임시 SSM secret 보관 문제를 확인하고 기존 Actions/정리 작업을 이어가도록 요청했다. [운영 26의 분석](../기획안설계/26_AWS_배포운영_실행가이드.md#첫-배포-키-임시-보관과-실패-정리)을 참고하고 [현재 운영 27](../기획안설계/27_Actions_첫배포_초기화_운영.md)에 반영했다.

## 구분

- 운영용 `shared/openai-api-key`: 서버 실행에 필요한 권위 있는 SecureString. 런타임 동안 유지하고 전체 초기화 시 삭제한다.
- 임시 공급용 `control/ikonly-demo/lifecycle/bootstrap/`: 첫 배포 전달을 위한 복제본. 소비 성공/실패 후 해당 세대 전체를 삭제해야 한다.
- 24시간 만료 필드는 소비 거부 기준이다. Standard Parameter의 물리적 자동 만료/삭제 기능을 추가한 것은 아니다.

## 구현 계약

| 항목 | 구현 |
|---|---|
| 등록 | 임의 generation ID 아래 chunk 저장·재읽기 hash 확인 → manifest → 활성 포인터 갱신 |
| 실패한 등록 | 새 세대만 제거; 기존 활성 세대 보존 |
| 소유권 | AWS 인증 후 GitHub run ID로 claim; 활성 consumer가 있는 동안 재공급/교체/sweep 거부 |
| 소비 검증 | 정확한 claim·count·만료·config hash·payload hash·승인 정책 원본 SHA256 |
| 조기 실패 | CI artifact 검증/다운로드 앞에서 claim; always에서 같은 run이 소유한 세대만 정리 |
| 정상/실패 종료 | 초기 배포 lock 아래에서 정확한 세대 삭제; 원시 결과 암호화 보존 |
| 잔여물 회수 | 다음 stage에서 작업 lock/claim 상태 확인 후 만료·미활성·미완성 세대 및 구 조각 회수 |
| 수동 회수 | 로컬 clear-supply, 정확한 환경명, 작업 lock, 실행 중 consumer 보호 |
| 삭제 실패 | 비밀 없는 generation/count/CLEANUP_FAILED 기록, 실패 반환 및 재시도 |

manifest는 비밀값 없는 generation/count/hash/config hash/expires_at/run_id를 String으로 보관한다. 실제 env/policy payload 조각만 SecureString이다. 포인터를 바꾸기 전 hash 검증이 끝나므로 일부만 쓴 설정을 정상 소비하지 않는다. 삭제 범위는 실제 세대 prefix 조회로 결정하고 과거 count로 추측하지 않는다.

## 검증

로컬 변경 영향 검사 **52 PASS**, Ruff check/format 통과. 등록 중 실패·조각 감소 재등록·만료/미완성 sweep·실행 중 consumer 보호·hash/config/만료/owner 검증 실패·dispatch 전 조기 실패·initial 성공/실패 종료·삭제 실패/재시도를 확인했다. 암호화 증거/정리 승인/IaC 재시도 기존 검증을 포함한다.

실제 SSM+Actions 조기 실패 시험과 후속 Linux CI는 완료 결과를 여기에 추가한다. 시험에는 **실제 OpenAI 키를 사용하지 않고 명백한 시험 문자열**을 공급하며, 유료 인프라 생성/LLM 호출 없이 claim/always 회수만 확인한다. 앞선 [Actions 전환 CI](2026-10-13_Actions_수명주기_전환과_AWS_초기화.md)의 715 PASS는 이번 보완 전 source의 결과다.

## 한계와 운영

AWS 인증 자체가 실패하거나 workflow가 시작되지 않으면 runner가 SSM을 삭제할 수 없다. 이 경우 로컬 clear-supply 또는 다음 stage의 sweep으로 회수한다. 만료 뒤 아무 작업도 실행하지 않으면 값이 물리적으로 남을 수 있으므로 보관을 취소할 때 clear-supply를 실행한다. 별도 유료 Advanced Parameter 만료 정책/상시 cleanup scheduler는 추가하지 않았다. 운영 키의 필요한 보관과 임시 복제본의 누락된 회수를 동일한 결함으로 설명하지 않는다.
