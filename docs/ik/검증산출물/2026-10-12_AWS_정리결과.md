# AWS 환경 정리 결과

## 최신: 전체 초기화 완료

2026-10-12 추가 사용자 요청에 따라 시험 증거를 로컬에 유지하고 AWS 보존 자원 21개도 모두 삭제했다. 아래 데이터 보존 방식의 정리는 중간 단계 이력이다. **현재 이번 환경의 실행 자원과 보존 저장 자원은 모두 제거된 상태**다. Windows 인증서 제거는 앞서 사용자가 보류했으므로 로컬에 남아 있다.

- 삭제: 암호화 DB 스냅샷 3개, ECR repository/이미지 2개, CloudWatch log group 8개, S3 객체/버킷 1개, SecureString Parameter 7개.
- 삭제 전에 `Environment` 및 `ManagedBy`/CloudFormation 소유 태그를 모두 확인했다. 로컬 배포/정리 증거 zip과 fault journal의 기존 SHA-256을 재검증했다.
- S3 모든 object version을 로컬 `test-results/aws-cleanup/s3-final-mirror/`에 내려받고 두 번 다운로드한 파일의 크기·SHA-256 일치를 확인했다. `purge-execution.json`에 원래 key/version과 로컬 파일 경로/hash를 보관했다. 로컬 개발 DB·환경 파일과 기존 계정 공유 자원은 변경하지 않았다.
- 최종 별도 AWS 조회에서 기존 실행 자원뿐 아니라 snapshot·repository·log group·bucket·환경 prefix Parameter가 모두 없음을 확인했다. 태그 검색에 남은 EC2/NAT 객체는 manifest의 대상이며 실제 상태가 `terminated`/`deleted`임을 대조했다. 과금 자원이 아닌 관리 이력이다.
- `purge-execution.json`, `purge-residual-check.json`에 실행·잔존 검사를 로컬 기록했다. 삭제한 S3에 최종 증거를 다시 업로드하지 않았다.
- 이번 환경의 향후 실행/저장 자원 과금 대상은 제거됐다. 이미 발생한 사용 요금은 남으며 계정 전체의 다른 자원 비용을 없앴다는 의미는 아니다. AWS에서 이 환경 데이터를 복원할 snapshot/key는 더 이상 없다.

첫 배포·부분/전체 업데이트·전체 초기화의 최신 기준과 구현/미구현 구분은 [배포 수명주기 25](../기획안설계/25_AWS_배포수명주기_정리.md)를 따른다.

## 이전: 데이터 보존 정리 상태

2026-10-12 사용자 요청에 따라 `ikonly-demo` 환경을 **데이터 보존 방식으로 정리 완료**했다. AWS 서울 리전의 소유 manifest·태그·인증 계정을 대조한 뒤 이번 환경의 자원만 삭제했다. 기존 기획안·게임 EIP 주소는 해제됐으며 더 이상 접속 주소로 사용하지 않는다.

AWS 정리는 완료됐지만 **Windows 루트 인증서 두 개의 삭제는 사용자 요청으로 보류**했다. 2026-10-12 재조회에서 두 지문 모두 `CurrentUser/Root`에 존재했다. 처음 삭제 완료 응답 이후 실제 저장소 조회로 남아 있음을 확인했고, 사용자가 최종적으로 보류를 선택했다.

배포와 사용자 시험의 과거 결과는 [실제 배포 기록](2026-10-12_AWS_실제배포_진행기록.md), [Edge 사용자 시험](2026-10-12_AWS_Edge_사용자테스트.md)을 보존한다. 정리 계약은 [구현 계획 24 §7](../기획안설계/24_AWS_배포_CICD_구현계획.md#7-생성정리-명령-계약)을 따른다.

## 정리 순서와 확인 결과

1. main/fault 점검 모드를 활성화하고 drain 성공을 확인했다. 임시 migration profile은 원래 main-api profile로 복구했다.
2. 5개 stack의 실제 자원 112개를 저장된 환경 manifest와 대조했다. Parameter Store와 수동 스냅샷을 포함한 계획은 삭제 111개·보존 20개였으며, RDS stack 삭제 중 생성되는 마지막 스냅샷 1개를 최종 보존 목록에 추가했다.
3. 최신 데이터의 암호화 수동 스냅샷 `ikonly-demo-final-20261012`가 `available`임을 확인한 뒤 RDS 삭제 보호를 해제했다. fault journal과 배포·사용자 시험 증거를 로컬 및 비공개 암호화 S3에 보관했다.
4. observability/application → data → access → network 순서로 삭제했다. 5개 stack 모두 `DELETE_COMPLETE`이고 마지막 삭제 완료 시각은 2026-10-12 14:12 KST다.
5. 클라우드 OpenAI 키 사본, runtime/MCP DB URL, 웹 인증 hash, 연결 증명 키 등 Parameter 10개를 삭제하고 복원용 Parameter 7개를 보존했다.
6. 별도 AWS 조회로 아래 실행 자원이 남지 않았음을 확인했다. 삭제된 EC2/NAT의 이력 객체가 조회되는 경우 `terminated`/`deleted` 상태를 확인했다.

| 자원 | 확인 결과 |
|---|---|
| EC2 6대 | 모두 `terminated`, 활성 인스턴스 0 |
| private RDS 1대 | DB 인스턴스 없음, 해당 자동 백업 잔존 없음 |
| NAT 1개·EIP 3개·VPC 1개 | 활성 NAT 없음, 기존 allocation/VPC 없음 |
| subnet·security group·VPC endpoint·ENI | 환경 소유/기존 VPC 자원 없음 |
| EBS | 환경/stack 태그 또는 해당 인스턴스 연결 기준 잔존 없음; 루트 볼륨은 DeleteOnTermination 설정 |
| IAM role·instance profile·SSM 배포 document | manifest의 자원 없음 |
| CloudWatch alarm·SNS topic | manifest의 자원 없음 |
| 일반 실행용 Parameter 10개 | 삭제 확인, 보존 대상 외 Parameter 없음 |

## 보존 자원과 비용

| 대상 | 보존 상태·목적 |
|---|---|
| RDS 스냅샷 3개 | 모두 암호화·`available`. 초기 seed, 최신 시험 데이터, CFN 삭제 시 마지막 snapshot |
| ECR repository 2개 | `ikonly-demo/application`, `ikonly-demo/web`; 검증된 이미지 보존 |
| CloudWatch log group 8개 | `/ikonly-demo/` 아래; 로그 이벤트 보존 기간 14일 |
| S3 bucket 1개 | Public Access Block 모두 활성, 서버측 암호화 설정 유지; 증거 객체 lifecycle 30일 |
| Standard SecureString Parameter 7개 | DB master/owner/role 비밀번호 및 URL 5개, main/fault LLM 기록 암호화 키 2개 |

스냅샷 식별자:

- `ikonly-demo-initial-20261012`
- `ikonly-demo-final-20261012`
- `ikonly-demo-data-snapshot-database-cnyryalx8qx8`

실행 자원을 삭제했으므로 해당 EC2/RDS/NAT/공인 IP의 사용 과금은 종료된다. **스냅샷·ECR·로그·S3 저장 비용은 남으며 전체 비용이 0이라는 뜻은 아니다.** 스냅샷·이미지·복원 키는 7일 뒤(10월 19일) 수동 재검토 대상으로 기록했다. 자동 삭제 예약을 만든 것은 아니다. 로그 이벤트 만료는 log group을 삭제하지 않고, S3 객체 만료도 bucket을 삭제하지 않는다.

스냅샷 복원을 실제로 실행한 시험은 하지 않았다. 백업의 `available`·암호화 상태와 증거 파일 내려받기 무결성을 확인했다. 복원 시 보존 DB URL의 endpoint를 새 RDS로 갱신해야 하며 기존 master/role 및 LLM 기록 키를 사용해야 한다. 같은 이름으로 IaC를 새로 생성하면 보존 repository/log group/bucket/Parameter와 충돌할 수 있으므로 재사용·import 또는 명시적 이름 처리 계획이 먼저 필요하다.

- fault journal: 13,392 bytes, SHA-256 `8dc9164147d86950d8b675b3094aaeac8117364d2aabda009ac665f26963004e`. 두 시험 run의 journal/checkpoint 4개 파일을 보관했다.
- 배포 증거 zip: 1,090,226 bytes, SHA-256 `628bb3469a9e742088cb03b4c1d3e484ad9e4d45fcd13ce87ee05bd1cfde7062`. S3 `cleanup/2026-10-12/deployment-evidence.zip`에 암호화 저장 후 다시 내려받아 SHA-256 일치를 확인했다.
- 최종 삭제 실행·잔존 검사·보존 목록·인증서 상태 기록도 S3 `cleanup/2026-10-12/cleanup-results.zip`에 별도로 암호화 저장하고 내려받기 SHA-256 일치를 확인했다. 크기·hash는 로컬 `final-evidence-upload.json`에서 확인한다.
- 로컬 `test-results/aws-cleanup/`의 Git 제외 기록: `plan.json`, `execution.json`, `maintenance-evidence.json`, `snapshot.json`, `evidence-upload.json`, `residual-check.json`, `retention.json`, `windows-ca-removed.json`.
- 비밀 환경 파일·실제 secret 값·인증서 개인 키는 문서/증거 zip/커밋에 포함하지 않았다. 로컬 `backend/.env`는 이번 클라우드 정리 대상이 아니다.

## 로컬 인증서 보류

삭제 명령은 자동 승인 검사에서 차단되어 실행하지 않았다. 이후 사용자가 수동 삭제를 시도했으나 두 인증서 모두 재조회에서 남아 있었고, 추가 제거는 보류했다.

| 저장소 | Subject | 지문 |
|---|---|---|
| CurrentUser/Root | Caddy Local Authority - 2026 ECC Root | `CA772EA2A558A2E4964BD36F03D21D49A5066CA3` |
| CurrentUser/Root | Caddy Local Authority - 2026 ECC Root | `223C31AAF26E42214F030663D62BFF30609C205E` |

다시 제거할 경우 `certmgr.msc`의 신뢰할 수 있는 루트 인증 기관에서 **이 지문과 일치하는 두 인증서만** 삭제하고 저장소를 재조회한다. 현재는 로컬 인증서 정리를 완료로 기록하지 않는다.
