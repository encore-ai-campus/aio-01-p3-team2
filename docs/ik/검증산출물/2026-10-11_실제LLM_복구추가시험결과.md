## 5. 검증 근거와 주입의 의미

- 요청의 목적/대상/기간/공간/행동/보상/연결 보존, Supervisor 소유 ID와 미션 매핑, EventPlan schema, 직접 계산한 재화 보상 상한과 근거를 검사했다.
- 실제 호출 usage와 암호화 DB 기록, 활성 정책 version/hash와 규칙 참조, 상태 버전/전이 연속성, 종료 후 추가 작업 차단, 저장 결과 및 멱등 재조회 provider 호출 0을 검사했다.
- 형식 오류는 실제 provider 응답의 업무 데이터를 첫 1회 또는 매회 변형했다. 변형 이전 원문/usage는 암호화 기록에 보존됐다. 최초 형식 오류는 실제 Planner 2회 + Critic 1회로 복구했다.
- 설명 불일치는 첫 실제 Critic 응답을 설명 수정 필요로 변형했다. 실제 Planner/Critic 각 2회, 기획 수정 1회로 완료했다. 고정 게임 설정을 바꿔 오류를 피하지 않았다.
- LLM timeout은 호출 경계의 상황 주입이다. 실제 OpenAI 서버를 중단하거나 실제 timeout이 발생했다고 주장하지 않는다. 일시 경우 다음 실제 Planner/Critic 각 1회로 복구했고, 지속 경우 호출 전 예외 4회로 종료되어 provider 전송은 0이다.
- MCP 503/절단/지연은 실제 HTTP proxy와 기존 MCP SDK의 transport 실패다. 일시 경우 Primary 재시도 1회 후 실제 MCP 응답과 이후 LLM 기획을 확인했다. 지속 경우 4회 실패 후 안전 중단했으며 provider 호출은 0이다.
- 실패 후 새 정상 요청이 정상 작동했다. 기존 Workflow를 강제로 재개하거나 정책 한도를 완화하지 않았다.

## 8. 가이드 산출물 연결과 한계

실제 LLM을 사용한 최종 기획안, 오류 검출→정책 결정→복구/종료→최종 결과, 트레이스/암호화 기록 참조, 실제 토큰·계산 비용, 실행 ID/화면 증빙을 확보했다. 기존 137개 결과와 함께 「배포 및 장애 복구 보고서」의 장애 시험 근거와 시연 자료로 사용할 수 있다.

이번 결과는 CI/CD·AWS 배포·외부 상용 게임 쓰기·복합 장애·공격 전수 시험의 완료 증빙이 아니다. LLM 복구 3종은 통제된 상황 주입이며 실제 provider 장애 전체를 재현하지 않는다. 기획의 사업 성과나 게임 적용 후 경제 효과가 실측됐다고 주장하지 않는다. 새 실제 생성 결과와 보안/정책 변경에는 별도 평가가 필요하다.
