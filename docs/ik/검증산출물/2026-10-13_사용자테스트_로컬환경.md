# 사용자 테스트 로컬 환경

2026-10-13, `ikonly`의 로컬 커밋 `a0a40f4` 기준으로 실행했다. DB 외 서버는 Windows에서 직접 실행하며 Edge에 두 화면을 열었다.

| 구성 | 주소 / 데이터 |
| --- | --- |
| 기획안 웹 | http://127.0.0.1:5177 |
| 게임 웹 | http://127.0.0.1:5173 |
| 일반 Backend | http://127.0.0.1:8004 |
| 일반 MCP | http://127.0.0.1:8010/mcp |
| 오류 시험 Backend / MCP | 8013 / 8014 |
| PostgreSQL | 127.0.0.1:5434, 기존 `ikonly-test-postgres-1` |
| 일반 / 오류 시험 DB | `eventquest_test` / `eventquest_fault_test` |

일반 Backend는 기존 `backend/.env`의 실제 LLM 모드·모델·비용 제한·암호화 키를 사용한다. DB/MCP/웹 주소는 위 로컬 연결로 공급했다. 비밀값을 문서와 실행 상태 파일에 기록하지 않았다. 오류 시험 서버는 실제 별도 DB/MCP와 결정적 LLM 응답을 사용한다.

## 준비 및 연결 확인

- 기존 게임·기획안 데이터는 보존하고 카탈로그/seed 및 migration 018을 적용했다. 게임을 초기화하지 않았다.
- 기존 활성 정책 166에 `ERR-DEP-MCP-003` 경로만 빠져 있었다. 기존 경로가 동일함을 확인하고 기본 대응 `RETRY_OPERATION / max_attempts=4`를 추가한 새 정책 167을 초안 생성→검증→활성화했다. 이전 버전과 감사 기록은 보존한다.
- 일반 API 및 MCP readiness 200, 두 웹의 게임 상태 프록시 200을 확인했다. 일반 MCP의 실제 `get_event_capabilities` 호출을 통과했다.
- 오류 시험 환경은 별도 DB, 상태 CLEAN을 확인했다.
- Edge 게임에서 기존 레벨 19, 재화·완료 이벤트·보상 기록이 표시됐다. 기획안 탭은 데모 로그인 화면으로 열었다.
- 이번 준비에서 유료 LLM 기획 요청을 실행하지 않았다. 키 인증·실제 생성 결과는 사용자가 기획안을 요청할 때 확인한다.

## 사용과 관리

기획안 화면은 시연용 아이디가 채워져 있으므로 **로그인** 버튼을 눌러 사용한다. 게임은 기존 진행 상태에서 바로 플레이할 수 있다. 기획안 생성→검토→승인→게임 등록 후 게임의 상태 새로고침으로 새 이벤트를 확인한다. `복구 시연`은 별도 시험 DB에서 실행된다.

이 PC에서 시작한 일반 MCP/API/게임의 소유 프로세스와 로그는 `backend/test-results/user-local/`, 기획안 웹은 `frontend-web/test-results/planning-ui-process.json`, 오류 시험은 `backend/test-results/fault-lab/servers.json`에 기록했다. 사용 중인 서버는 이번 작업 종료 후에도 유지한다. 종료 요청 시 이 기록의 PID와 실행 명령을 대조해 해당 서버만 종료한다. DB 데이터는 삭제하지 않는다.

다른 PC의 설치/실행/종료는 [팀원 로컬 가이드](../팀원_로컬실행_사용자가이드.md)를 따른다. 이 환경은 AWS 배포와 독립이다.
