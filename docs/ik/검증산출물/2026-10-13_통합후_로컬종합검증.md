# 통합 후 로컬 종합 검증

## 기준과 목적

- 기준: `ikonly`, 통합 커밋 `505bbb8` 및 아래 검사에서 보완한 스키마/테스트 파일.
- 목적: 부분 통합 검사를 넘어 전체 기본 회귀, 실제 DB/MCP, 기획안·게임 화면, 격리 오류 대응의 연결 문제를 확인한다.
- 실제 테스트 DB는 기존 로컬 PostgreSQL 서버의 별도 `eventquest_comprehensive_test`, 화면 보조 검사는 `eventquest_merge_test`, 오류 시험은 `eventquest_fault_test`를 사용했다. 업무 DB와 AWS 환경은 사용하지 않았다.
- API·MCP·웹 서버는 검사 단계별로 실행했다. 다른 작업의 5184 서버가 이미 실행 중이어서 해당 서버를 종료하거나 재사용하지 않고 오류 경로 검사는 5214에서 진행했다.

## 발견한 문제와 조치

| 문제 | 원인과 조치 |
| --- | --- |
| 체크인된 Brief/Plan JSON Schema 두 파일이 현재 모델과 불일치 | 새 자동 보상/보상 정책 계약이 모델에만 반영되어 있었다. 공식 export script로 생성 파일을 갱신했고 `--check`를 통과했다. CI에서 배포를 차단할 문제였다. |
| Provider 스키마 단위 검사 실패 | strict provider는 모든 필드를 요구하지만 Backend는 과거 명시 보상 기록의 `reward_proposals` 생략을 빈 목록으로 허용한다. 이 차이를 명시하고 제안 항목의 필드·타입·한도까지 비교하도록 보완했다. 계약을 완화하지 않았다. |
| 마이그레이션 개수 검사 실패 | 018 추가 후 기대 개수가 18로 남아 있었다. 19개 및 마지막 018 이름을 검사한다. 실제 신규/기존 DB 적용도 통과했다. |
| 실제 MCP 503 종료 Trace 검사 실패 | 안전 중단 이후 `storage.result_persisted`가 추가되는 현재 흐름을 이전 마지막 이벤트 기대값으로 검사했다. 안전 중단→저장 완료 순서와 Supervisor SAFE_STOP, 재조회 동일성을 함께 검사한다. |
| 브라우저 증거 파일 충돌 | 경로 시험의 기본 출력 폴더가 다른 실행의 하위 증거를 정리했다. `playwright.path.config.js`의 출력 폴더를 `test-results/fault-path-sync`로 분리했다. 중간 실패는 기능 장애가 아닌 시험 결과 경로 충돌이며, 분리 후 화면 검사를 통과했다. |
| 새 결과 제목을 이전 PASS 제목으로 검사 | 공유 프론트 검사에서 완료 제목과 판정 설명을 각각 검사하도록 변경했다. 제목만으로 복구 성공을 판정하지 않는다. |

게임/기획/복구의 업무 실행 코드는 이번 검사에서 변경하지 않았다. 변경은 생성 JSON Schema, 회귀 검사 및 시험 출력 격리에 한정된다. 신규 게임 화면 검사는 기존 두 조회 검사에 강화·스테이지·던전 쓰기와 재조회 검사를 추가한다.

core의 1 SKIP은 DB가 없는 core 실행에서 PostgreSQL factory를 제외한 것이다. 해당 저장소 롤백 검사는 별도 DB 실행에서 3개 모두 통과했다. 화면 종합 34개에는 실제 DB 연결 검사와 13개 진행 그래프 fixture 검사가 함께 포함된다.

강화 화면의 실제 요청→강화 단계 증가→새로고침 후 재화 표시, 스테이지/일반 던전 전투→일시 정지→저장된 재화 표시를 검사했다. 저장한 두 전투 후 화면을 직접 확인하여 배경·캐릭터/몬스터·던전 구분·게임 정보·이벤트 공간 표시를 확인했다. 이는 모든 해상도/모든 스킨에 대한 디자인 승인을 의미하지 않는다.

격리 HTTP 검사에서는 잘못된 환경 필드, 허용되지 않는 재시도 조합, 외부 Origin을 거절했고 오류 시험이 BUSY인 동안 일반 기획 요청은 주입 영향을 받지 않았다. 시험 완료 후 환경 CLEAN을 확인했다.

일반/시험 Backend를 한 화면으로 연결한 최종 Edge 검사 5개도 모두 통과했다. 검사 과정에서 대체 포트 5214만 Origin에 허용한 상태로 5177 쓰기를 시도했을 때 403을 확인했다. 현재 검사 포트를 명시적으로 허용하여 재실행했으며 보안 검사 자체는 완화하지 않았다.

## 증거와 재실행

- `test-results/comprehensive-2026-10-13/`: `core.xml`, `postgres.xml`, `atomic.xml`, `fault-path-real.xml`, `fault-suite.json`, 네 단계 `ui-*.xml`, `unified.xml`, 단계별 로그.
- `test-results/ui-connected.xml`, `ui-restart.xml`, `ui-game.xml`, `ui-mcp503.xml`: CI와 같은 네 단계의 화면 결과.
- `frontend-web/test-results/ci-game/`: 전투 후 스크린샷.
- `frontend-web/test-results/comprehensive-real/`: 실제 주입 보고서·관측 사건 애니메이션·실패 시 Trace.
- 실제 CI 실행 절차는 `infra/ci/run-python.sh`, `infra/ci/ui.py`, 분류는 `infra/test-suites.json`을 따른다. 이번 Windows 실행은 기존 Python 환경에서 수행했고 DB 비밀값은 프로세스 메모리에서만 공급했다.

이번 검사 과정의 최초 실패와 수정 이유는 위 표에 남겼다. 최종 XML은 수정 후 완료 상태다. 과거 통합/장애 시험 보고서를 덮어쓰지 않았다.

## 검증 제한

- 유료 OpenAI 실호출은 하지 않았다. LLM 생성·복구 응답은 결정적 어댑터를 사용했으므로 실제 모델의 품질/토큰 비용 재검증은 별도다.
- 이번 28개 기본 오류와 추가 경로 검사가 과거 137개 정책 조합/복합 오류 전체의 재실행을 뜻하지 않는다.
- 운영 이미지/HTTPS fleet 검사는 이번 native 로컬 실행에서 제외했다. Docker는 DB 및 일회성 TLS DB 검사에 사용했다. AWS 자원 생성·배포·원격 Actions는 실행하지 않았다.
- 기능 검증 통과가 모든 사용자 행동·모든 브라우저·장기 부하에서 오류가 없음을 보장하지 않는다.

## 종료 상태

검사에서 시작한 일반 API·오류 시험 API·MCP·웹과 일회성 TLS DB를 종료했다. 기존 `ikonly-test-postgres-1` 및 다른 작업의 5184 서버는 유지한다. 시험용 데이터와 로컬 증거는 보존한다. 기존 `.vite/` 캐시는 커밋에서 제외했다. `pre/` 문서는 변경하지 않았다.

최종 결과는 Python 651개 PASS(core의 DB 미설정 1 SKIP은 별도 원자성 검사로 보완), 브라우저 49개 PASS, Node 4개 PASS, 전체 기본 오류 28/28 PASS다. Python/화면/오류 실행은 서로 다른 검증 범위이므로 하나의 시나리오 수로 합산하지 않는다.
