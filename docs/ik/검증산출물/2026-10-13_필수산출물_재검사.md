# 필수 산출물 재검사: 가이드·구현·시험 대조

기준일: 2026-10-13 (Asia/Seoul). 이번 정정은 제출본 v1.1이며 이전 v1은 Git 이력에 보존한다. 대상은 [필수 산출물 대문](../필수산출물_README.md)과 제출본 3종이다. 코드와 이미 수행한 시험을 읽어 대조했으며, 새 장애 시험·유료 LLM 호출·AWS 재배포는 수행하지 않았다. `pre` 원문은 변경하지 않았다.

## 1. 결론

**문서 3종은 가이드 §4의 포함 내용을 갖추고 있으며, 아래 정정 후 핵심 구조·수치·실행 결과는 실제 근거와 일치한다. 다만 가이드 전체 수행·제출 체크의 완전 충족은 아니다.**

## 3. 원본 재대조 결과

### 아키텍처·정책·배포 코드

- Planner `canonical-planner-input/output.v2`, Critic `canonical-critic-input/output.v1` 및 StrictContract를 확인했다.
- `Handoff.request/validate_receiver/accept`, canonical Planner/Critic 생성·호출부에서 필드·버전·소유권을 확인했다. accept는 입력/출력 검증 후 수행한다.
- `Supervisor.transition/record_recovery_decision`과 canonical persist/멱등성/라이프사이클 기록을 확인했다. 상태 선택과 DB CAS/transaction의 역할을 구분한다.
- recovery_policy의 활성 정책 pinning, code별 허용 action, 보안/계약/결과 불명 쓰기의 retry 제한을 확인했다. 모든 오류를 무조건 복구한다는 주장은 없다.
- cloud DB의 verify-full/DB·role identity 검사 및 시험 API deterministic/key-free guard를 확인했다. 실호출 자식 fixture의 범위를 원 보고서와 일치시켰다.
- CI needs/gate의 failed/skipped/missing 차단과 lifecycle 입력/확인 hash, 7일 artifact 보존을 확인했다. IaC observability는 EC2 18 + RDS 1 = 19 alarm이며 SNS email 구성과 실제 수신은 구분한다.

## 4. 가이드 기준의 남은 간극

1. **알림 수신·에스컬레이션:** §6 파이프라인 체크의 직접 미충족 부분이다. GitHub 결과·Step Summary/로그와 SNS 구성을 이메일 도달 확인으로 대체할 수 없다. 다음 승인된 환경에서 수신 확인·성공/실패/지연 통보·후속 조치를 시험해야 한다.
2. **Handoff 기술 retry 문맥:** §3 권장 단계의 실패 원인/재시도 횟수 전달이 충분하지 않다. 현재 retry_count=0/error_context={}이며 기술 재시도 관측은 snapshot/Trace에 있다. 반면 의미 revision은 Critic reason을 다음 Planner context에 넣는다. 이는 코드 개선 항목이지 문장만 고쳐 완료할 수 있는 항목이 아니다.
3. **발표 실행 정보:** 현재 삭제된 AWS IP는 실행 URL이 아니다. 정상/복구 시연의 과거 증거는 있지만 지금 발표 가능한 라이브 환경이나 완성 영상이라는 뜻은 아니다. 팀 정보·영상/슬라이드·로컬 시연 방식은 별도 준비해야 한다.
4. **지표 범위:** 127은 팀의 사전 선정 모집단이다. 전체 장애를 말할 때 제외된 보안/CAS를 숨기면 안 된다. 본문에 전 표본과 제외 기준을 공개했고 실제 LLM 오류 9개는 모두 포함했다.
5. **범위 외 운영:** 다중 사용자 RBAC·migration 후 자동 DB 복원·Redis 운영·복합 장애·장기 부하는 완료 근거 없음. 가이드 예시 전략을 모두 구현해야 한다는 뜻은 아니며, 이번 실제 구조와 시험 범위를 설명하는 한계다.

## 5. 제출 판단

3종 보고서는 실제 결과를 설명하는 제출 문서로 사용할 수 있다. **모든 가이드 요구가 완전히 검증됐다고 발표하거나 모든 체크박스를 완료 처리해서는 안 된다.** 특히 알림 수신의 미검증과 기술 retry Handoff 간극을 공개한다. 기존 source별 실패·수동 개입과 과거 시험 보고서는 보존한다.
