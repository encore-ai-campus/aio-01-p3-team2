## 4. 문서 마무리와 남은 한계

1. **알림 요구:** 실제 수신까지 충족해야 한다면 다음 승인된 환경에서 SNS 구독 확인·성공/실패/지연 알림·담당자 후속 조치를 시험한다. 이번 문서에서는 미검증으로 제출하며 가이드 §6의 해당 체크를 완료하지 않는다.
2. **마무리 범위:** 당시 문서 마무리에서는 코드 수정·추가 시험·발표 시연 안내 작성을 제외했다. 이후 사용자 요청으로 main 전환과 첫 배포·수용 검사를 진행해 현재 AWS는 ACTIVE다. 과거 실행 증거·발표 자료는 보존하며 발표 시연 안내는 새로 작성하지 않았다.
3. **팀 표지:** 팀장 본인 외 팀원 실명·정확한 담당 및 프로젝트 기간은 사용자 확인 없이 만들어 쓰지 않는다. 제출 규격상 필요한 값은 팀에서 표지에 기입한다.
4. **기술 한계:** Handoff 기술 retry 문맥 전달, 다중 역할 권한, migration 후 데이터 복원, 실제 RDS 중단·복합 오류·장기 부하는 향후 범위로 명시한다. 문서 마무리를 위해 구현 완료로 바꾸지 않는다.

문서 3종은 정리 완료했으나 위 부분 충족/미검증 항목이 남으므로 가이드 모든 체크를 일괄 완료 처리하지 않는다.
