## 3. 공개할 한계와 후속 과제

| 항목 | 현재 판단 | 후속 작업 |
|---|---|---|
| 성공·실패·지연 알림과 에스컬레이션 | 구성·로그는 있으나 실제 수신/후속 조치 미검증. 가이드 해당 항목 부분 충족 | 승인된 환경에서 수신과 담당자 후속 조치를 검증 |
| 기술 재시도 Handoff | retry_count/error_context의 다음 에이전트 입력 전달 부족. 상태·Trace의 재시도 기록과 의미 revision 피드백은 별도 존재 | 오류 문맥·시도 횟수 계약 및 영향 시험 보완 |
| 운영 확장 | 다중 사용자 RBAC, migration 후 자동 DB 복원, Redis 운영, 복합 장애·장기 부하의 완료 근거 없음 | 필요성과 우선순위를 정한 뒤 별도 설계·구현·시험 |
| 팀 표지 | 팀원 실명·최종 담당·프로젝트 기간을 임의 확정하지 않음 | 제출 시 팀에서 확인한 정보 기입 |

문서 3종은 실제 구현과 시험 결과를 설명하는 제출본으로 사용할 수 있다. 모든 가이드 요구를 완전히 검증했다고 표현하지 않는다. 위 후속 작업은 이번 문서 마무리 범위에 포함하지 않는다.

## 4. 루트 README 확정 구성

루트 README는 처음 방문한 사람이 프로젝트 목적·구조·실행 진입점을 이해하는 문서로 둔다. 상세 계약·시험 사례·설계 이력은 [IK 문서 라우터](README.md)와 해당 문서에서 관리한다. 2026-10-13 사용자 요청에 따라 아래 구성을 적용했다. 프로젝트 소개는 제목 아래 본문으로 두고 나머지 항목을 7개 절로 구성했다.

| 순서 | 제목 | 넣을 내용 |
|---|---|---|
| 1 | 프로젝트 소개 | Opong Heroes 이벤트 기획·검수·사람 승인·게임 적용, 멀티 에이전트와 정책 기반 복구 목적 |
| 2 | 핵심 기능 | 기획/검증, 승인/적용, 게임 진행/보상, 정책 관리, 격리 오류 시험, 배포 수명주기 |
| 3 | 시스템 구조 | 기획안·게임 프론트, 일반·시험 Backend/MCP, DB 격리, Planner/Critic와 Supervisor 관계를 간단한 Mermaid로 표현 |
| 4 | 로컬 실행 | 필요한 도구와 실행 가이드 링크. 기본 결정적 모드와 실제 LLM 모드, 개인 환경 설정을 구분 |
| 5 | 구현·검증 상태 | 기준 날짜/커밋, CI 및 AWS 시험별 결과, AWS 초기화 상태. 지표는 분모와 증거 링크 병기 |
| 6 | 필수 산출물·상세 문서 | 산출물 3종, 현재 구현 상태, 설계·검증 라우터, 보존 가이드로 연결 |
| 7 | 한계와 후속 개선 | 알림 수신 미검증·Handoff 기술 retry 문맥 및 운영 확장 범위 |

루트에서 현행 프로젝트 문서의 탐색 경로는 `docs/ik/`로 모은다. 실행 명령은 기존 로컬 실행 가이드와 대조한 것만 싣고, 환경 설정의 비밀값이나 삭제된 AWS IP를 현재 접속 주소로 싣지 않는다. 과거 팀 문서·기획안 전체 목록은 루트에 나열하지 않는다.
