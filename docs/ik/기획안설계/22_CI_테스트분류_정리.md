## 1. 판정 기준과 범위

현재 호출 가능한 기능·계약·보안 불변조건을 검증하면 유지한다. 파일 이름이 Backend A/B 또는 legacy라는 이유만으로 삭제하지 않는다. 호환 Task API와 transport alias가 실제 구현에 남아 있어 해당 회귀 검사는 필요하다. 실행 내용이 없는 파일, 사라진 UI만 검증하는 검사, 현재 계약의 더 강한 검사와 중복되고 실행 입력도 더 이상 생성되지 않는 검사는 제거한다.

Python 65개 파일에서 빈 파일 5개를 제거하고 분류 검증 파일 1개를 추가해 **61개**가 됐다. JavaScript 테스트는 새 게임 화면 검사 파일을 포함해 **7개**다. 매개변수화된 실행 사례 수와 소스 함수 수를 구분한다. backend 테스트 함수 본문을 정규화한 비교에서 완전히 같은 본문은 발견하지 못했다. 목적이 비슷한 단위·API·DB 검사는 서로 다른 경계를 검증하므로 보존했다.

실행 분류와 함수 목록은 저장소의 `infra/test-suites.json`으로 관리한다. pytest 시작 시 누락·삭제·중복 파일, 미분류 Python 함수 변경, 빈 Python 파일, 미분류 JavaScript 파일을 검사한다. JavaScript 개별 함수 변경의 의미 검토는 코드 리뷰로 수행한다. 분류 목록은 테스트 내용을 대신하지 않는다.

## 3. 제거·수정·보충

### 제거

- `backend/tests/test_fault_injection.py`, `test_guard.py`, `test_retry.py`, `test_routing.py`, `test_validation.py`: 모두 0바이트이며 실행 사례가 없었다. 해당 기능의 실제 검사는 unit·workflow·Supervisor·fault-lab 테스트에 남아 있다.
- `planning-flow`의 옛 fault demo 검사: `#fault-type` 등 삭제된 UI를 사용했다. 현재 fault-lab 수용 검사와 backend 오류 정책·runner 검사가 담당한다.
- `planning-flow`의 옛 restart 검사: 현재 writer는 `space_workflow` 계약만 생성하므로 영구 skip 상태였다. 더 강한 `workflow-connected`의 durable restart 검사가 상태 버전·Runtime ID·미션 수·reconciliation을 확인한다.

### 기존 검사 수정

- 복구 시연의 현재 제목에 맞춰 navigation 기대값 수정. 시험 Backend가 꺼진 상황을 fixture로 고정해 일반 navigation이 사용자 시험 서버에 의존하지 않게 했다.
- PostgreSQL recovery restart 자식 프로세스에 `FAULT_LAB_MODE=isolated` 추가. 시험 프로세스의 격리 설정 누락을 해결했다.
- 무조건 생성되는 screenshot은 Playwright `test-results`로 이동했다. 과거 문서의 증빙 이미지를 재실행으로 덮어쓰지 않는다. 명시적인 증빙 출력 옵션은 유지한다.
- fault-lab 기본 UI 주소를 통합 UI 5177로 수정했다.
- core에서는 오케스트레이션 재시도 대기만 생략한다. backoff 계산 자체는 별도 테스트에서 jitter 범위·지수 증가·상한을 검증한다. postgres/local에서는 이 생략을 적용하지 않는다.

### 새 검사

- 게임 Runtime 5개 함수/7개 사례: 높은 스테이지의 외형 주기·스탯·보상 증가, 성장/강화 비용 증가, 던전 파티·보스 주기, 몬스터 공격/패배, 재화 소비·멱등성·잔액 부족 불변, 스킨 구매/장착/탈착.
- 테스트 분류 3개: 목록의 완전성, 기본 로컬 실행의 외부/호환 제외, 미분류 테스트 추가 차단.
- 게임 Edge 2개: 실제 API 값과 화면의 일치·canvas/탭 표시·조회 중 POST 0, 503 시 가짜 연결 상태 표시 방지.

게임 E2E는 화면 연결 smoke 검사다. 실제 전투·성장·보상 쓰기는 Runtime/API/DB 검사에서 확인한다. 스프라이트 미감·전투 연출의 완성도는 별도의 사람 검토 항목이며 자동 smoke만으로 완벽한 게임 UX를 주장하지 않는다.

## 5. 실행 및 CI 연결 기준

저장소 루트에서 실행한다. 의존성 설치 및 자동 검사 DB 컨테이너 준비는 기존 로컬 환경을 전제로 한다.

```powershell
# DB/외부 API 없이 빠른 회귀 + schema/Ruff
pwsh -NoProfile -File infra/test-local.ps1 -Profile core

# 실제 DB 통합 검사 또는 전체 Python 게이트
pwsh -NoProfile -File infra/test-local.ps1 -Profile postgres
pwsh -NoProfile -File infra/test-local.ps1 -Profile local

# Python + schema/Ruff + 두 build + proxy/UI fixture + DB E2E/게임/restart
pwsh -NoProfile -File infra/verify-local.ps1

# 호환 기능은 별도 선택
pwsh -NoProfile -File infra/test-local.ps1 -Profile compatibility
```

자동 검사 DB는 `eventquest_auto_test`로 제한한다. 일반 사용자 DB `eventquest_test`와 시험실 `eventquest_fault_test`를 초기화하지 않는다. PostgreSQL 자동 검사와 DB E2E는 같은 자동 검사 DB를 사용하므로 순차 실행한다. E2E 기본 API/UI는 8015/5195, 게임 화면은 5193으로 사용자 서버와 구분한다. 실행 helper는 자신이 시작한 임시 API를 종료한다.

`verify-local.ps1`의 구성 단계는 각각 실행해 검증했다. 전체 wrapper를 한 번에 실행한 기록은 이번 점검에 포함하지 않는다. core/compatibility는 로컬 Python, postgres/local은 기존 캐시된 테스트 runner와 DB 컨테이너를 사용한다. 일반 사용자 Backend를 Docker로 바꾸지 않는다.

외부 검사는 `backend/.venv/Scripts/python.exe -m pytest --test-profile=external --allow-external`로 명시하고 격리 환경에서 필요한 URL/키를 설정한다. `--collect-only`도 허용 옵션이 필요하다. 키를 CI 기본 secret으로 요구하지 않는다.

현재 `.github/workflows`는 예전 yejin frontend 배포/인프라 작업이며, 이번 테스트 분류를 실행하는 신규 GitHub CI는 아직 구성하지 않았다. 이번 변경은 로컬 품질 게이트와 테스트 실행 경계의 준비다. 다음 CI 작업에서는 core→PostgreSQL→build/proxy/UI fixture→DB E2E를 독립 job으로 연결하고, 실패 시 배포를 차단해야 한다. 선택적 외부 실험과 역사적 증빙 조회는 기본 job에 넣지 않는다. 원격 CI 통과나 배포 완료로 해석하지 않는다.

수치형 line coverage는 측정하지 않았다. 현재 충족 여부는 정책/계약/상태·경제 불변조건/연결 시나리오 기준이며, 새로운 기능은 분류 목록과 해당 회귀 검사를 함께 추가한다. `pre/` 및 과거 보고서는 수정하지 않았다.
