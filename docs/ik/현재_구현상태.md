# 현재 구현 상태

## 문서 상태와 기준선

- 상태: 코드 확인 기반 스냅샷
- 확인일: 2026-10-09 (Asia/Seoul)
- 브랜치/커밋: `feature/checkpoint` / `4ba7ef27a305656dd38bea99b94a7b3f8b927b3b`
- 작업 트리: 애플리케이션 코드 변경은 확인하지 않았으며 `docs/ik/` 전체가 미추적 상태다. 이 문서 및 설계 문서의 미추적 상태 자체는 커밋되었다는 뜻이 아니다.
- 검사 범위: 현재 체크아웃의 소스·설정 파일 정적 확인. 이 문서 작성 중 테스트는 실행하지 않았다.
- 역할: 현재 코드의 상세 근거 목록이다. 전체 목표와 As-Is/To-Be의 상위 요약은 [최상위 시스템 설계서 §6, §16](최상위_시스템_설계서.md#16-현재-상태-목표-주요-차이)을 따른다.

## 요약

현재 저장소에는 **이벤트 기획·멀티 에이전트 검수·승인 후보 생성과 운영 화면**, **게임 데이터 조회용 MCP**, **승인된 기획안을 읽어 전투 화면에 표시하는 정적 데모**가 있다. 그러나 가상 게임 Runtime의 서버 권위 행동 판정, 이벤트 등록, 진행도/보상 지급, Runtime 상태의 PostgreSQL 영속화는 없다. 따라서 현재 게임 화면의 전투 완료나 골드 변화는 실제 게임 미션 완료·보상 지급을 뜻하지 않는다.

## 컴포넌트별 구현 상태

| 영역 | 상태 | 코드에서 확인한 내용 | 남은 경계 |
|---|---|---|---|
| 운영자 UI | 구현 | `frontend/app.py`, `frontend/pages/`, `frontend/components/`에 Streamlit 로그인·기획 입력·결과·Trace·운영 화면이 있다. 로그인은 허용 ID를 확인하는 데모 방식이며 비밀번호 인증이 아니다. | 게임 플레이 화면과 동일 UI가 아니며 실제 인증/권한 시스템도 아니다. |
| 기획 API | 구현 | `backend/app/main.py`, `backend/app/api/event.py`에서 `/api/events/generate`, `/api/tasks`, Task 상세·삭제·승인·Trace·tool log API를 등록한다. 요청/응답은 Pydantic schema로 표현한다. | 가상 게임 적용/플레이 API는 없다. |
| Agent Workflow | 구현 | `backend/app/agents/`, `backend/app/orchestration/`, `backend/app/services/workflow_service.py`에 Planner, Balance & Rule, Critic, Supervisor, routing/retry/handoff 및 Mock/MCP/Live 실행 선택이 있다. | 설정에 따라 Mock/외부 의존 경로가 달라진다. 이 코드는 가상 게임 Runtime이 아니다. |
| 승인 | 구현 | Task는 workflow/critic/approval 상태와 `result_version`을 갖고, 승인·수정 요청은 `task_service`와 기존 approval API에서 처리한다. | 가상 게임 Runtime용 불변 승인 스냅샷·digest 기반 적용 영수증과는 별개다. |
| 게임 규칙 검증 | 부분 구현 | `backend/app/rules/game_rule_engine.py`, `backend/app/agents/balance_rule.py`, `backend/app/services/clash_event.py`가 기획안 입력의 일부 콘텐츠·미션·보상 가능성을 검증한다. | 게임 플레이 command, 성장, 입장, action 결과, Runtime 미션 aggregate, 보상 지급 판정이 아니다. |

| 테스트 코드 | 존재, 실행 결과 미확인 | `backend/tests/`, `mcp_server/tests/`, `demo-game/tests/`에 테스트 코드가 있다. | 이번 상태 확인에서 테스트를 실행하지 않았으므로 통과 여부를 말할 수 없다. |

## 현재 게임 데모에서 실제로 일어나는 일

1. 사용자가 승인 완료 Task ID를 입력하면 로컬 Python HTTP 서버가 백엔드에서 Task를 조회한다.
2. 승인·검수 상태를 통과한 Task에서 이름·기간·미션·보상 등의 표시 데이터를 추린다.
3. 브라우저 JavaScript가 지정된 몬스터 이동·공격 횟수·Day 전환·시연용 골드를 화면 상태로 처리한다.
4. 백엔드에는 게임 행동, 미션 진척, 인벤토리 변경, 보상 지급 요청이 전달되지 않는다.
5. 새로고침 시 브라우저 상태가 초기화되며, 이벤트 상태 및 게임 진행의 영속 복원은 없다.

이에 따라 현재 화면의 “시연 완료”는 전투 애니메이션 진행 완료 표시다. Runtime이 기획 미션을 달성했다고 확인한 상태로 해석하면 안 된다.

## 구현 계획과 코드의 구분

[가상 게임 구현 계획서](가상게임_구현계획서.md)의 Phaser 3/Vite, 신규 `backend/app/game/`, `/api/game/*`, Runtime SQL 및 저장소, API proxy 확장은 모두 **예정**이다. 이 코드가 현재 checkout에 이미 들어 있다고 표현하지 않는다. 구현이 시작되면 브랜치와 커밋을 갱신해 이 스냅샷을 다시 확인한다.
