# 게임 검증·밸런스 설계서

## 목적·상태

- 상태: WP-09 결정적 게임 단독 시뮬레이터가 스테이지 1:1과 일반 폐광 1:3 encounter를 같은 규칙 함수로 계산한다. 1,000-step 및 10,000-step 성장 fixture에서 정체 없이 진행됐고, 10,000-step에서 던전 보스 1,371회 승리·폐광 적 처치 20,565회를 계산했다. DB/API 성공·멱등과 브라우저 UI 로딩을 확인했으며, 패배·재시도 경계와 실제 전투 애니메이션 수용은 남아 있다. 기획안별 난이도·보상 영향 평가는 WP-10 범위다.
- 목적: 먼저 가상 게임의 전투·성장·재화 루프가 장기 진행 가능한지 검증하고, 이후 그 결과를 기획안의 난이도·보상 영향 평가에 재사용한다.
- 상위 기준: [가상 게임 도메인 상세 설계서](../가상게임_도메인_상세설계서.md) §§7–10, GD-04–GD-07
- 의존: [게임 규칙](01_게임규칙_플레이루프.md), [데이터·스키마](02_게임데이터_스키마.md)
- 구분: 여기서는 게임/기획 도메인 검증을 다룬다. 서비스 복구·재시도 정책은 별도다.

## WP-09 게임 단독 밸런스 검증 구현

실행 명령은 `backend\\.venv\\Scripts\\python.exe -m backend.scripts.simulate_game_balance --steps 10000`이다. `--growth disabled`는 성장 없는 비교 fixture다. Runtime과 같은 카탈로그·전투·성장 계산을 사용하며, 단계/폐광 승패, 성장, GOLD·MOON_SHARD 흐름, 첫 클리어 GEM, 3종 스킨 구매 결과를 JSON으로 출력한다. 이 도구는 대표 가상 유저의 규칙 시뮬레이션이며 DB 트랜잭션/동시성 수용을 대신하지 않는다.

게임 밸런스 검증은 기획안 Workflow에 의존하지 않는다. 고정 가상 유저가 스테이지와 폐광을 진행하고, 실패 후 farm, XP/레벨 상승, GOLD 강화, MOON_SHARD 누적/소비를 반복하는 simulator를 만든다. 입력은 하나의 ruleset/data snapshot과 세그먼트성 시작 fixture이며 출력은 구간별 전투 횟수/승패, 성장 속도, 재화 유입·소비·잔액, 막힘 또는 과잉 구간이다. GEM 흐름은 첫 클리어 stage 5·10·15 각 1개 지급과 스킨 상점 3종 각 1개 구매로 모델링한다. 상점 구매는 전투력에 영향을 주지 않으며 모든 상품을 살 수 있는지와 지급 이후 잔액을 시뮬레이션한다.

WP-09 통과 기준은 플레이 상한을 두지 않는 수식이 고레벨/고층에서도 계산 가능하고, 시작·기준·성장 가속 fixture에서 장기 진행 루프와 강화 재화 소비가 설명되는 것이다. 이는 무한 범위 전체의 완전한 수학적 증명이 아니라 대표 구간과 큰 입력 경계에 대한 결정적 검증이다. 계수 변경은 새 profile/data 버전으로 보존한다.

## WP-10 기획안 검증 파이프라인 (게임 수용 이후)

1. 구조 검증: schema version, 필수 필드, 타입, 범위
2. 참조 검증: game/content/action/item/segment/template ID와 활성 버전
3. 게임 규칙 검증: 이벤트 유형·필수 미션·기간·입장·한도·보상 조건
4. 달성 가능성: 세그먼트 프로필, 시작 상태, 이벤트 일수, 성장·시도 상한
5. 경제 영향: 개인 및 집단 지급량, 기준 획득량 대비 비율, 보유 상한 위험
6. 결과 종합: `valid`, `warning`, `blocked` 및 근거 목록

스키마/참조/필수 규칙 오류 또는 핵심 입력 결손은 `blocked`다. 유효하지만 기준 플레이보다 높은 노력이 필요하거나 선택적 집단 추정치가 없는 경우 `warning`이다. 필수 평가가 모두 완료되고 경고도 없을 때 `valid`다. 각 finding은 코드, field path, 설명, 계산근거, 버전 참조를 갖는다.

검증 실행은 결과 재현에 필요한 전체 입력을 고정한다: 이벤트 설정 digest, `event_schema_version`, `game_ruleset_version`, `game_data_snapshot_id`, progression/combat/economy profile IDs, `balance_policy_version`, 세그먼트 fixture 버전, 평가 시각(UTC), 검증기 버전이다. 외부 데이터나 현재 시각을 암묵적으로 다시 조회해 과거 평가 결과가 바뀌지 않게 한다. 재평가는 새 실행 ID와 새 근거를 만들고 이전 결과를 덮어쓰지 않는다.

## 달성 가능성 계산

각 세그먼트 프로필은 평가 시작 시점의 레벨/성장 상태, 기준 행동량, 콘텐츠별 사용량을 제공한다. 평가기는 이벤트 기간, 해금 조건, 경험치 임계치 함수, 전투/보상 진행 함수와 콘텐츠 시도 한도를 적용해 기준 달성량과 규칙상 최대 달성량을 계산한다. 일반 폐광은 시도 한도가 없으므로 최대치는 기간과 명시된 기준 행동량 또는 정책상 계산 예산으로 제한한다. 이벤트 특별 던전 등 유한 템플릿은 해당 템플릿의 시도·층 한도를 쓴다.

- `reachable`: 목표가 기준 프로필의 달성량 이내이며 입장 조건 충족
- `at_risk`: 기준 달성량을 넘지만 규칙상 최대 달성량 이하
- `unreachable`: 필요한 콘텐츠가 열리지 않거나 목표가 규칙상 최대를 초과
- `insufficient_data`: 필수 프로필·성장·기간·제한 버전이 없거나 불일치

예측 확률을 만들지 않는다. 행동량 프로필은 fixture의 가정이며, 실제 유저 통계인 것처럼 표시하지 않는다. `insufficient_data`는 승인 판단이 불가능하므로 상위 기준에 따라 차단한다.

## 보상 영향

보상별로 유저당 최대 지급량을 `수량 × 최대 수령 횟수`로 계산한다. 가능한 경우 세그먼트 예상 참여자 수를 곱해 집단 총량을 산출한다. 결과는 같은 기간의 기준 획득량 비율과 기존 보유량/보유 상한 위험을 함께 제시한다. 예상 참여자 수가 선택 입력으로 없으면 유저 단위 결과는 계산하고 집단 합계는 생략하며 경고한다. 보상·기준 획득량·상한이 필수 데이터인데 누락되면 차단한다.

허용/주의/위험 임계값은 아직 수치로 고정하지 않는다. fixture 결과를 팀이 검토한 뒤 정책값과 근거를 결정한다. 이 수치는 플레이 규칙과 분리된 balance/policy version으로 관리하는 방안을 권장한다.

WP-10의 이벤트 보상 평가는 화폐·재료에는 기준 수급량 대비 지급 비율과 상한 위험을 적용한다. 스킨은 화폐로 임의 환산하지 않고 보유 가능 인원, 유저당 중복 여부, 중복 보상 처리, 획득 난이도를 별도 표시한다. 중복 스킨 보상 정책이나 아이템 참조가 비어 있으면 승인 검증을 차단한다.

## 최소 fixture와 시나리오

### 일반 던전 파티 전투 수용 시나리오 (설계 목표, 미구현)

| 상황 | 기대 결과 |
|---|---|
| 일반 층 파티 구성 | 적 3명이 결정된 순서로 생성되고 스테이지 몬스터 ID/아트와 겹치지 않음 |
| 5층 보스 구성 | 별무리 광맥룡 1명과 폐광 호위 2명. ID·이름·아트가 서로 일치 |
| 영웅 공격 | 가장 앞선 생존 적 1명을 공격. 처치하면 HP 0에서 멈추고 다음 라운드는 다음 생존 적을 타깃 |
| 적 반격 | 생존 파티 중 고정 회전 순서의 1명만 영웅을 공격. 쓰러진 적은 건너뜀. 같은 입력이면 같은 적이 공격 |
| 파티 처치 성공 | 마지막 적 처치 즉시 전투 종료, 층 성공·보상·`dungeon_cleared`는 한 번만 생성 |
| 영웅 패배 | 영웅 HP 0 즉시 종료, 층 진척/성공 행동/보상은 불변. 파티별 처치 수는 로그에만 남음 |
| 층 재도전 | 최대 HP 영웅과 모든 적의 시작 HP를 복원. 이전 시도에서 처치한 적 상태가 이월되지 않음 |
| push/farm 경계 | push 패배는 최고 클리어 층 farm으로 전환하고, farm 승리는 같은 층을 유지 |
| 이벤트 특별 던전 | 일반 폐광의 파티 구성이 암묵 적용되지 않고 승인된 템플릿 구성만 적용 |

장기 시뮬레이터는 던전 파티 encounter를 같은 결정 규칙으로 실행하고, 적 수 증가에 따른 전투 라운드·영웅 패배율·층별 XP/GOLD/MOON_SHARD 및 강화 가능성을 비교한다. 5층 보스 주기의 난이도 급등 여부도 관찰한다. 파티 구성이나 계수 변경은 새 데이터/profile 버전으로 고정한다.

### 합의한 스테이지·성장 수용 시나리오

스테이지/전투 규칙을 구현할 때 다음을 추가 검증한다. 정확한 스탯·증가율은 밸런스 fixture 확정 전까지 예시값을 제품 규칙으로 간주하지 않는다.

| 상황 | 기대 결과 |
|---|---|
| 스테이지 전투 승리 | 성공 Attempt/Action과 보상·경험치를 한 번 기록하고, 최고 클리어 및 다음 사냥 스테이지를 갱신 |
| 스테이지 전투 패배 | 실패 Attempt만 남기고 성공 미션/보상은 생성하지 않으며, 다음 사냥 위치를 최고 클리어 스테이지로 설정 |
| 영웅 HP 경계 | 몬스터 타격으로 영웅 HP가 정확히 0이 되면 즉시 패배; HP가 1 이상이면 전투 계속 |
| 몬스터 HP 경계 | 영웅 타격으로 몬스터 HP가 정확히 0이 되면 즉시 승리하고 몬스터 반격은 실행하지 않음; HP가 1 이상이면 교전 계속 |
| 한 번의 타격이 남은 HP보다 큰 피해 | 대상 HP는 0에서 멈추고 초과 피해는 음수 HP로 표시/저장되지 않으며 즉시 종료 |
| 5개 슬롯 경계(5→6, 10→11, 15→16) | 시각 슬롯이 1→1로 순환하고 몬스터 표현은 반복되며 새 주기의 능력치·보상 프로필이 의도한 버전으로 적용 |
| 로비 강화 성공 | 강화 비용 차감, 영웅 전투 능력치 증가, 변경 원장이 같은 논리 처리로 기록됨 |
| 로비 강화 거절 | 비용 재화 부족 또는 저장 표현 범위 초과면 능력치와 잔액 모두 불변; 게임 rank 상한은 없음 |
| 자동 전투 명령 재전송 | 동일 request ID는 기존 판정 반환, 전투·보상·진행 추가 없음 |
| 일반 던전/이벤트 특별 던전 | 기존 폐광은 일일 시도권 없이 층을 생성하며 성장·보상 곡선을 적용; 이벤트 특별 던전은 승인된 유한 층·시도 규칙을 준수; 별도 탑 상태는 생성하지 않음 |

스테이지와 폐광은 양의 정수 인덱스 전 구간에서 계산이 끝나야 한다. 시뮬레이션은 첫 15개 fixture 경계와 이후 각 5슬롯 반복 주기를 포함해 대표 레벨/rank 진행을 실행한다. 단계별 예상 승패와 로비 강화 횟수를 함께 비교해 장기 정체, 승리 불가능 구간, 보상/강화 비용의 발산을 찾는다. 기준 성장에서도 일정 기간 진행이 가능한지와 패배 후 최고 클리어 파밍이 유지되는지 확인한다. 기준 프로필과 가정은 실제 유저 통계가 아니라 데모 밸런스 값으로 표시한다.

무한 진행은 수학적으로 무한한 수치를 저장한다는 뜻이 아니다. 각 생성 함수는 입력 범위, 정수/오버플로 처리, 계산 비용 상한을 정하고 게임 규칙상 인위적인 최종 층은 두지 않는다. DB/API 표현 범위에 가까워지면 조용히 잘라내지 않고 명시적 용량 오류를 반환하며, 해당 범위 이전에 플레이 밸런스가 성립하는지 검증한다.

경제 검증은 모든 재화/재료에 대해 생성원과 소비처를 연결한다. GOLD는 스테이지·폐광 보상과 강화 소비의 장기 비율을 비교한다. MOON_SHARD는 획득 주기와 강화 소비처를 함께 설계한다. GEM은 무료 첫 클리어 milestone이 지급하고 고정 스킨 상점이 소비한다. 상점 3종을 모두 구매한 뒤 남는 GEM은 전투력으로 전환하지 않으며, 초과 잔액은 꾸미기용 선택지/향후 WP-10 이벤트 보상에 쓸 수 있는 데모 잔액으로 표시한다. simulator는 구매 전후 성장 시점과 총 지급/소비량을 확인한다.

필수 fixture는 (a) 낮은 레벨 신규 유저, (b) 기준 성장 유저, (c) 복귀/고성장 유저 후보, (d) 유한 이벤트 콘텐츠의 기간/시도 제한, (e) 보유 상한에 가까운 보상 수령 상태, (f) 높은 stage/floor와 강화 rank의 수치 안정성을 포함한다. fixture마다 데이터 출처가 아닌 “데모 가정”임을 표시하고 snapshot/profile/policy version을 지정한다.

전투 규칙 fixture에는 영웅/몬스터 HP가 1일 때의 타격, 초과 피해 clamp, 양측 선공 종료, 강화 비용 경계, stage 5→6·10→11 슬롯 경계, push 패배 전환과 farm 반복을 포함한다. 같은 상태·명령·ruleset/snapshot은 같은 combat_log와 결과를 반환해야 한다.

시뮬레이션/밸런스 계산과 플레이 API는 같은 규칙 함수 또는 동등성 검증된 규칙 구현을 사용한다. 화면 연출은 규칙 계산에 들어가지 않는다. 분리 구현을 선택한다면 대표 fixture 전체에서 결과 일치가 수용 조건이다.

### 대표 수직 시나리오 수용 계약

아래 수직 이벤트 시나리오는 게임 단독 WP-09 완료 뒤 WP-10에서 실행한다. 유한·지속 운영과 반복 보상 정책이 입력과 결과에 모두 나타나야 한다.

이 시나리오는 승인 이벤트 적용부터 유저 보유 보상까지의 논리 연결을 검증한다. fixture의 숫자는 밸런스 주장이나 상용 게임 값이 아니며, 이 시나리오를 처음 구현할 때 고정하는 데모 데이터다.

1. 특별 던전 이벤트 승인 결과를 적용한다. 같은 `task_id/result_version/digest` 재요청은 같은 `runtime_event_id`와 영수증을 돌려주고, digest가 바뀌면 충돌한다. 시작 전에는 `scheduled`, 시작 시각부터 종료 전까지 `active`, 종료 시각부터 `ended`다.
2. 데모 유저가 활성 이벤트의 특별 던전에 처음 접근한다. 세그먼트 조건을 평가해 한 번만 참여 스냅샷을 만든다. 자격이 없으면 진행·시도권 차감 없이 거절하고 참여를 만들지 않는다.
3. 현재 층의 몬스터 HP/공격력 fixture로 도전한다. 승리면 층 진행과 보상을 한 번 기록하고, 패배면 Attempt/combat_log만 기록한다. 동일 request_id 재전송은 최초 결과를 돌려주며 추가 전투·차감·보상은 없다.
4. 일반 스테이지를 성공해 카탈로그 경험치를 받고 레벨을 올린다. 이 성공 ActionRecord와 파생 레벨 마일스톤은 서로 연결된다. 이벤트 ID를 보내지 않은 일반 행동은 특별 던전 미션에 집계되지 않는다.
5. 특별 던전의 현재 층을 재도전해 성공한다. 성공 Attempt와 `special_dungeon_progressed` ActionRecord가 연결되고 현재 층이 한 번만 완료된다. 다음 층으로 이동하며 기존 층 반복으로 추가 미션 수를 얻지 못한다.
6. 보스 층을 성공해 목표 미션을 완료한다. 진행도 완료, 보상별 RewardRecord 생성, 유저 VirtualInventory 잔액 증가가 한 논리 트랜잭션으로 반영된다. 같은 명령 재전송이나 같은 ActionRecord 재집계는 미션/잔액/원장을 추가 변경하지 않는다.
7. 이벤트 종료 경계에서는 새 플레이 변경을 거절하고, 기존 적용 영수증·행동/미션/보상 기록과 현재 보유 상태는 조회 가능하다.

이 시나리오의 모든 레코드는 동일한 고정 이벤트 버전과 게임 규칙/데이터 참조를 추적한다. 물리 API/테이블 이름은 03–05 문서의 논리 엔티티를 구현 기술로 매핑하되 위 관찰 가능한 결과를 바꾸지 않는다.

| 사례 | 기대 결과 |
|---|---|
| 유한 이벤트 | `end_at` 전에는 active, 종료 시각부터 ended; mission/reward는 설정한 유저별 총 횟수를 넘지 않음 |
| 지속 이벤트 | `end_at=null`, 수동 종료까지 active; 달성·경제 영향은 지정된 평가 기간(기본 제안 30일)으로 계산 |
| 일/주 반복 미션 | cycle 전환 시 progress를 새로 계산하고 `cycle_id`를 바꿔 이전 지급과 중복되지 않음 |
| 반복 보상 한도 | cycle/user 상한 검사와 inventory delta가 같은 원자 처리로 확정 |
| 스킨 보상 | 소유/장착 가능한 catalog skin을 지급; 중복 지급은 ItemDefinition 정책대로 처리하고 보유 수를 경제 영향에 표시 |
| 목표가 기준 달성량 이하 | reachable, 차단/경고 없음 |
| 기준량 초과·최대량 이내 | at_risk, warning |
| 최대 시도/성장으로도 목표 불가 | unreachable, blocked |
| 성장 프로필 또는 제한 데이터 부재 | insufficient_data, blocked |
| 참여자 수만 부재 | 유저별 영향 표시, 집단 영향 생략, warning |
| 보상량/보유 상한 기준 부재 | blocked |
| 비활성 item/action ID | 참조 오류, blocked |

## 완료 기준과 미결

- WP-09: 게임 fixture만으로 무한 stage/폐광 층, 성장, 강화, 재화/재료 소비, 스킨 소유/장착을 실행하고 저장 상태를 재조회할 수 있다.
- WP-09: 첫 클리어 GEM 지급, 고정 스킨 3종 구매, 잔액 부족/중복 구매 거절, 구매 후 재접속 복원이 검증된다.
- WP-09: 시뮬레이터와 Runtime이 같은 규칙/카탈로그 버전에서 대표 combat/reward 결과를 낸다.
- WP-10: 기존 기획안 연동에서 유한 이벤트와 지속 이벤트 각각 reachable/warning/blocked 사례가 있고, 반복 보상/스킨 정책이 재현된다.
- 각 이벤트 유형에 최소 하나의 reachable, warning, blocked 사례가 있다.
- fixture와 계산 출력만으로 결과를 재현할 수 있다.
- 경제 정책 임계값과 예상 참여자 산정이 결정 기록에 연결되고, 시도권 검증이 MVP `Asia/Seoul` 자정 초기화 기준으로 재현된다.
- 평가 결과와 승인 대상 버전이 연결되어 이후 같은 입력으로 재현 가능하다.
- 시작/종료 및 레벨/시도 한도 경계 테스트와 중복 재처리가 데이터 버전별로 재현된다.
- 무한 stage/floor/level/rank profile이 경계 입력에서 결정적이고 유한한 계산 비용으로 동작하며 밸런스 시뮬레이션과 Runtime 판정 결과가 동일 fixture에서 일치한다.
- 반복 획득 재화마다 소비처가 있거나 명시적 전용 정책이 있고, 한 이벤트 검증 결과에서 게임 규칙·snapshot·balance policy 버전을 재현할 수 있다.
