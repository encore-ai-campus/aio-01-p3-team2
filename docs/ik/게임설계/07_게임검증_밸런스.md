# 게임 검증·밸런스 설계서

## 목적·상태

- 상태: 검증 입력·결과 및 종단 수용 계약 정리 완료, 밸런스 데이터 수치 미결
- 목적: 이벤트 설정이 게임 규칙상 가능하고 보상 영향이 설명 가능한지 재현 가능한 기준으로 평가한다.
- 상위 기준: [가상 게임 도메인 상세 설계서](../가상게임_도메인_상세설계서.md) §§7–10, GD-04–GD-07
- 의존: [게임 규칙](01_게임규칙_플레이루프.md), [데이터·스키마](02_게임데이터_스키마.md)
- 구분: 여기서는 게임/기획 도메인 검증을 다룬다. 서비스 복구·재시도 정책은 별도다.

## 검증 파이프라인

1. 구조 검증: schema version, 필수 필드, 타입, 범위
2. 참조 검증: game/content/action/item/segment/template ID와 활성 버전
3. 게임 규칙 검증: 이벤트 유형·필수 미션·기간·입장·한도·보상 조건
4. 달성 가능성: 세그먼트 프로필, 시작 상태, 이벤트 일수, 성장·시도 상한
5. 경제 영향: 개인 및 집단 지급량, 기준 획득량 대비 비율, 보유 상한 위험
6. 결과 종합: `valid`, `warning`, `blocked` 및 근거 목록

스키마/참조/필수 규칙 오류 또는 핵심 입력 결손은 `blocked`다. 유효하지만 기준 플레이보다 높은 노력이 필요하거나 선택적 집단 추정치가 없는 경우 `warning`이다. 필수 평가가 모두 완료되고 경고도 없을 때 `valid`다. 각 finding은 코드, field path, 설명, 계산근거, 버전 참조를 갖는다.

검증 실행은 결과 재현에 필요한 전체 입력을 고정한다: 이벤트 설정 digest, `event_schema_version`, `game_ruleset_version`, `game_data_snapshot_id`, 세그먼트 fixture 버전, 경제 정책 버전, 평가 시각(UTC), 검증기 버전이다. 외부 데이터나 현재 시각을 암묵적으로 다시 조회해 과거 평가 결과가 바뀌지 않게 한다. 재평가는 새 실행 ID와 새 근거를 만들고 이전 결과를 덮어쓰지 않는다.

## 달성 가능성 계산

각 세그먼트 프로필은 평가 시작 시점의 레벨/성장 상태, 일일 기준 행동량, 던전 사용량을 제공한다. 평가기는 이벤트 기간의 실제 일수와 초기화 규칙, 해금 레벨, 행동별 경험치, 시도 한도를 적용해 기준 달성량과 규칙상 최대 달성량을 계산한다.

- `reachable`: 목표가 기준 프로필의 달성량 이내이며 입장 조건 충족
- `at_risk`: 기준 달성량을 넘지만 규칙상 최대 달성량 이하
- `unreachable`: 필요한 콘텐츠가 열리지 않거나 목표가 규칙상 최대를 초과
- `insufficient_data`: 필수 프로필·성장·기간·제한 버전이 없거나 불일치

예측 확률을 만들지 않는다. 행동량 프로필은 fixture의 가정이며, 실제 유저 통계인 것처럼 표시하지 않는다. `insufficient_data`는 승인 판단이 불가능하므로 상위 기준에 따라 차단한다.

## 보상 영향

보상별로 유저당 최대 지급량을 `수량 × 최대 수령 횟수`로 계산한다. 가능한 경우 세그먼트 예상 참여자 수를 곱해 집단 총량을 산출한다. 결과는 같은 기간의 기준 획득량 비율과 기존 보유량/보유 상한 위험을 함께 제시한다. 예상 참여자 수가 선택 입력으로 없으면 유저 단위 결과는 계산하고 집단 합계는 생략하며 경고한다. 보상·기준 획득량·상한이 필수 데이터인데 누락되면 차단한다.

허용/주의/위험 임계값은 아직 수치로 고정하지 않는다. fixture 결과를 팀이 검토한 뒤 정책값과 근거를 결정한다. 이 수치는 플레이 규칙과 분리된 balance/policy version으로 관리하는 방안을 권장한다.

## 최소 fixture와 시나리오

필수 fixture는 (a) 낮은 레벨 신규 유저, (b) 기준 성장 유저, (c) 복귀/고성장 유저 후보, (d) 기간 중 일일 제한이 걸리는 던전, (e) 보유 상한에 가까운 보상 수령 상태를 포함한다. fixture마다 데이터 출처가 아닌 “데모 가정”임을 표시하고 snapshot/version을 지정한다.

규칙 엔진 fixture에는 경계값 쌍도 포함한다. 콘텐츠 `entry_level` 바로 아래/동일/위, `clear_level` 바로 아래/동일/위, 이벤트 시작 시각/종료 시각 직전·경계, 일일 초기화 직전·직후, 이미 소비한 시도권, 이미 집계한 `action_id`, 이미 지급된 보상을 재실행한다. 입력 상태·명령·규칙/데이터 버전이 같을 때 검증 결과와 ActionRecord 핵심 필드(서버 시각 제외 가능)는 같아야 한다. MVP 권위 판정에 난수를 쓰지 않으므로 같은 fixture의 성공/실패와 보상 계산은 항상 일치해야 한다.

시뮬레이션/밸런스 계산과 플레이 API는 같은 규칙 함수 또는 동등성 검증된 규칙 구현을 사용한다. 화면 연출은 규칙 계산에 들어가지 않는다. 분리 구현을 선택한다면 대표 fixture 전체에서 결과 일치가 수용 조건이다.

### 대표 수직 시나리오 수용 계약

이 시나리오는 승인 이벤트 적용부터 유저 보유 보상까지의 논리 연결을 검증한다. fixture의 숫자는 밸런스 주장이나 상용 게임 값이 아니며, 이 시나리오를 처음 구현할 때 고정하는 데모 데이터다.

1. 특별 던전 이벤트 승인 결과를 적용한다. 같은 `task_id/result_version/digest` 재요청은 같은 `runtime_event_id`와 영수증을 돌려주고, digest가 바뀌면 충돌한다. 시작 전에는 `scheduled`, 시작 시각부터 종료 전까지 `active`, 종료 시각부터 `ended`다.
2. 데모 유저가 활성 이벤트의 특별 던전에 처음 접근한다. 세그먼트 조건을 평가해 한 번만 참여 스냅샷을 만든다. 자격이 없으면 진행·시도권 차감 없이 거절하고 참여를 만들지 않는다.
3. 현재 층의 `clear_level`보다 유저 레벨이 낮은 상태에서 도전한다. 결과는 실패 Attempt와 1회 시도권 차감이며, ActionRecord·미션 진척·성장·보상 변화는 없다. 같은 `request_id` 재전송은 실패 결과를 반환하되 추가 차감은 하지 않는다.
4. 일반 스테이지를 성공해 카탈로그 경험치를 받고 레벨을 올린다. 이 성공 ActionRecord와 파생 레벨 마일스톤은 서로 연결된다. 이벤트 ID를 보내지 않은 일반 행동은 특별 던전 미션에 집계되지 않는다.
5. 특별 던전의 현재 층을 재도전해 성공한다. 성공 Attempt와 `special_dungeon_progressed` ActionRecord가 연결되고 현재 층이 한 번만 완료된다. 다음 층으로 이동하며 기존 층 반복으로 추가 미션 수를 얻지 못한다.
6. 보스 층을 성공해 목표 미션을 완료한다. 진행도 완료, 보상별 RewardRecord 생성, 유저 VirtualInventory 잔액 증가가 한 논리 트랜잭션으로 반영된다. 같은 명령 재전송이나 같은 ActionRecord 재집계는 미션/잔액/원장을 추가 변경하지 않는다.
7. 이벤트 종료 경계에서는 새 플레이 변경을 거절하고, 기존 적용 영수증·행동/미션/보상 기록과 현재 보유 상태는 조회 가능하다.

이 시나리오의 모든 레코드는 동일한 고정 이벤트 버전과 게임 규칙/데이터 참조를 추적한다. 물리 API/테이블 이름은 03–05 문서의 논리 엔티티를 구현 기술로 매핑하되 위 관찰 가능한 결과를 바꾸지 않는다.

| 사례 | 기대 결과 |
|---|---|
| 목표가 기준 달성량 이하 | reachable, 차단/경고 없음 |
| 기준량 초과·최대량 이내 | at_risk, warning |
| 최대 시도/성장으로도 목표 불가 | unreachable, blocked |
| 성장 프로필 또는 제한 데이터 부재 | insufficient_data, blocked |
| 참여자 수만 부재 | 유저별 영향 표시, 집단 영향 생략, warning |
| 보상량/보유 상한 기준 부재 | blocked |
| 비활성 item/action ID | 참조 오류, blocked |

## 완료 기준과 미결

- 각 이벤트 유형에 최소 하나의 reachable, warning, blocked 사례가 있다.
- fixture와 계산 출력만으로 결과를 재현할 수 있다.
- 경제 정책 임계값과 예상 참여자 산정이 결정 기록에 연결되고, 시도권 검증이 MVP `Asia/Seoul` 자정 초기화 기준으로 재현된다.
- 평가 결과와 승인 대상 버전이 연결되어 이후 같은 입력으로 재현 가능하다.
- 시작/종료 및 레벨/시도 한도 경계 테스트와 중복 재처리가 데이터 버전별로 재현된다.
- 밸런스 시뮬레이션과 Runtime 판정 결과가 동일 fixture에서 일치한다.
