# 게임 규칙·플레이 루프 설계서

## 문서 상태와 범위

- 상태: WP-09 규칙 구현 반영. 스테이지·성장 규칙은 opong-rules-1.2.0에서 유지하고, 일반 던전 1:N 전투는 opong-rules-1.3.0으로 구현했다. 던전 파티 밸런스와 DB/브라우저 수용 확인은 별도 완료 기준을 따른다.
- 목적: 모바일 방치형 RPG 데모의 플레이 규칙과 이벤트 미션 근거가 되는 행동을 정의한다.
- 상위 기준: [가상 게임 도메인 상세 설계서](../가상게임_도메인_상세설계서.md) §§3–5, 7–9
- 다음 연결: [데이터·스키마](02_게임데이터_스키마.md), [검증·밸런스](07_게임검증_밸런스.md)
- 제외: 구체 밸런스 수치, 물리 저장/API, 에이전트 워크플로우

## 설계 원칙

1. 플레이 판정의 권위는 게임 Runtime에 둔다. 프론트엔드는 입력과 결과 표현을 담당한다.
2. 이벤트 기획은 허용된 게임 기능을 선택·설정하며 임의 코드를 추가하지 않는다.
3. 같은 게임 상태와 같은 행동 입력은 같은 결과를 내야 한다.
4. 임의 보상·경험치 지급은 허용하지 않고 버전이 지정된 규칙 데이터만 사용한다.

## 최소 플레이 루프

`로비 성장 확인/강화 → 스테이지 또는 일반 던전 자동 도전 → 승리 시 다음 단계 / 패배 시 최고 클리어 단계에서 반복 사냥 → 자원·경험치 획득 → 계속 성장`

일반 던전 자체가 반복 도전 가능한 연속 층 진행 콘텐츠다. 별도의 도전의 탑은 만들지 않는다. 이벤트 특별 던전은 이벤트 기획이 정한 유한한 층 구성으로 운영한다. 플레이 행동은 게임 Runtime 판정 후 성장·이벤트 미션·보상에 반영한다.

| 콘텐츠 | 규칙 책임 | 이벤트 근거 행동 |
|---|---|---|
| 스테이지 | 해금 순서와 권장 레벨을 확인하고 성공/실패를 판정한다. | `stage_cleared` |
| 일반 던전 | 연속 층 순서, push/farm, 층별 전투·보상·최고 기록을 판정한다. | `dungeon_cleared` |
| 이벤트 특별 던전 | 활성 이벤트 및 등록된 템플릿 설정이 있을 때만 입장시킨다. 층/보스 완료를 판정한다. | `special_dungeon_progressed` |
| 성장 | 허용 행동의 경험치 보상과 누적 경험치 임계치를 적용한다. | `growth_milestone_reached` |

### 합의된 플레이 방향

- 스테이지는 순차적으로 자동 도전한다. 승리하면 다음 스테이지로 이동하고, 패배하면 최고 클리어 스테이지로 돌아가 자동 사냥을 이어간다. 플레이어는 로비 성장 후 다음 미개방 스테이지를 다시 밀 수 있다.
- 자동 진행은 `push`와 `farm` 두 모드로 구분한다. `push` 중 승리하면 다음 스테이지로 진행한다. 미개방 다음 스테이지에서 패배하면 자동으로 `farm` 모드로 전환하고 최고 클리어 스테이지를 반복 사냥한다. 아직 클리어한 스테이지가 없으면 카탈로그 첫 스테이지를 farm 대상으로 사용한다. `farm` 중에는 승리해도 다음 스테이지로 자동 재도전하지 않는다. 플레이어가 로비에서 성장한 뒤 `다음 스테이지 도전`을 선택하면 `push`로 전환한다. 이로써 실패한 상위 스테이지를 무한 반복하지 않는다.
- 사냥 일시정지는 진행 중인 서버 명령/재생 중인 전투 결과를 취소하지 않고, 현재 결과 처리가 끝난 다음 전투 요청을 보내지 않는 의미다. 재개는 현재 모드(`push` 또는 `farm`)를 유지한다.
- 몬스터 외형/아키타입은 5개 스테이지 슬롯 단위로 순환한다. `cycle = floor((stage_index - 1) / 5)`, `slot = ((stage_index - 1) % 5) + 1`로 프로필을 고르고, 버전이 고정된 성장 곡선으로 HP·공격·방어·XP·재화 보상을 계산한다. 1–15구역은 현재 데이터를 초기 보정 표본으로 보존하고 16구역부터 계산 프로필을 적용한다. 성장률 계수는 밸런스 수용 시뮬레이션으로 확정한다.
- 전투 장면에는 영웅과 몬스터가 서로 공격하는 교전, 양측 HP, 공격·피격·처치 피드백을 둔다. 한 전투 라운드는 영웅 공격 후 몬스터가 생존해 있으면 몬스터가 반격하는 순서로 처리한다. 공격을 받은 쪽 HP는 피해만큼 감소하고 0 아래로 내려가지 않게 한다. 몬스터 HP가 먼저 0이 되면 승리, 영웅 HP가 먼저 0이 되면 패배하며 해당 타격 직후 전투를 종료한다. 서버가 최종 전투 결과와 상태 변화를 판정하고, 화면은 이를 애니메이션으로 표현한다.
- 레벨·영웅 스탯·무기/갑옷 강화는 게임 플레이 상한 없이 증가한다. 현재 영웅 레벨 8과 강화 5단계 제한은 구현 fixture의 상한이며 목표 규칙에서는 제거한다. 성장 임계치·스탯 증가량·강화 비용은 한 버전의 성장 프로필에서 계산한다.
- 일반 던전은 기존 별무리 폐광 안에서 층이 계속 이어지는 성장 재료 콘텐츠로 만든다. 층은 push 승리 시 전진하고 패배하면 최고 클리어 층을 farm한다. 별도 탑 콘텐츠는 만들지 않는다. 이벤트 특별 던전은 승인 설정의 유한 층을 유지한다.
- 전투 규모는 콘텐츠별로 분리한다. 스테이지는 영웅 1명 대 몬스터 1마리 규칙을 유지하고, 일반 던전 별무리 폐광은 영웅 1명 대 적 파티 3마리의 동시 전투로 설계한다. 5층마다 광맥룡 보스와 폐광 전용 호위 2마리가 함께 등장한다. 이 1:N 규칙은 현재 구현이 아니라 다음 구현 범위이며 이벤트 특별 던전에는 자동 적용하지 않는다.
- GOLD는 스테이지/던전 보상으로 지속 획득하고 무기/갑옷 강화로 소비한다. 다른 잔액도 성장 루프에 남길 경우 획득처와 소비처를 함께 정의한다. 잔액 상한은 게임 규칙의 조기 종료 조건으로 두지 않고 저장소 표현 범위와 분리한다.

### 연속 진행·성장 규칙 목표

| 영역 | 진행 규칙 | 성장·보상 규칙 |
|---|---|---|
| 스테이지 | 양의 정수 `stage_order`를 사용한다. 첫 구간을 제외하고 직전 순번을 클리어해야 다음 순번 해금; 추가 레벨 잠금은 두지 않는다. `n=stage_order`, `visual_slot=((n-1)%5)+1`; push 승리 시 +1, 패배 시 최고 클리어 farm | 1–15구역은 현재 fixture 그대로 보존한다. 16 이후 후보식: HP=`111+6×(n−15)`, ATK=`12+ceil((n−15)/2)`, DEF=`3+floor((n−15)/5)`, XP=`105+5×(n−15)`, GOLD=`22+(n−15)`. 프로필 버전에서 계산한다. |
| 일반 던전 | 기존 별무리 폐광이 양의 정수 `floor_index` 기반의 무한 층 push/farm 진행을 맡는다. 첫 층 이후 직전 층 클리어가 다음 층 해금 조건이다. 진행/최고 층과 누적 성공 횟수는 스테이지와 별도로 저장한다. encounter는 적 3명, 5층 배수는 보스 1명+호위 2명이다. 일일 입장 한도 없음 | `f=floor_index`. 기존 1층 적 기준에서 이후 후보식: HP=`72+6×(f−1)`, ATK=`10+ceil((f−1)/2)`, DEF=`2+floor((f−1)/5)`, XP=`80+5×(f−1)`, GOLD=`15+(f−1)`. 수식은 encounter 기본 스탯/층 보상에 적용하고 적 역할별 계수는 데이터 버전에서 관리하며 시뮬레이션 후 확정한다. 폐광 누적 성공 5회마다 MOON_SHARD 1개를 지급한다. |
| 영웅 레벨 | 레벨 상한 없이 누적 XP로 계산한다. 현재 임계치 표본을 정확히 연장하는 목표식은 `T(1)=0`, `T(L)=15×L×(L−1)+10` (`L≥2`)이다. | 현재 HP `90+12×(L−1)+18×armor_rank`, ATK `11+2×(L−1)+4×weapon_rank`의 선형 성장 규칙을 유지하고 더 높은 레벨에서도 같은 방식으로 계산한다. |
| 강화 | 무기·갑옷 rank 상한을 제거한다. | 무기·갑옷 rank 1–5 비용은 현재 표본을 보존한다. rank 6부터 무기 비용=`110+20×(rank−5)`, 갑옷 비용=`100+18×(rank−5)` GOLD를 후보로 둔다. 다음 rank가 10, 15, 20…이면 MOON_SHARD 1개를 추가 소비한다. |
| 재화 | GOLD는 stage/dungeon 반복 보상 및 강화 비용이다. MOON_SHARD는 폐광 성공 5회당 1개를 얻고 강화 rank 이정표에서 소비한다. GEM은 첫 클리어 stage 5·10·15에서 각 1개를 얻고, 고정 스킨 상점에서만 소비한다. 전투력 구매에는 쓰지 않는다. | 각 재화/item은 생성원·소비처·상한 정책을 명시한다. 임의 잔액 상한이 진행을 막지 않게 하고 보상/소비 비율은 경제 검증한다. |

MOON_SHARD 획득과 강화 rank 이정표 소비를 연결한다. 첫 클리어 stage 5·10·15에서 GEM을 지급하고 고정 스킨 3종을 각 1 GEM에 판매한다. 이벤트의 반복 주기와 경제 영향 평가는 WP-10에서 다룬다. 연장식은 15개 기존 stage와 성장/폐광 표본을 기준으로 구현하고 `backend.scripts.simulate_game_balance`로 장기 진행을 비교한다.

현재 Runtime은 위 HP/능력치 기반 전투를 사용한다. 이전 clear_level 비교는 opong-rules-1.0.1 기준의 구현 이력이다. 새 판정은 opong-rules-1.1.0 및 opong-data-1.1.0으로 고정한다.

전투는 연출 난수 없이 서버에서 결정적으로 계산한다. 전투 시작 때 영웅 HP를 최대치로 복구하며, 피해·HP·승패 로그는 동일 규칙과 카탈로그 버전으로 재현한다.

### 현재 구현 규칙: HP 기반 결정 전투

#### 일반 던전 1:N 전투 목표 계약 (미구현)

- 일반 층은 폐광 전용 적 3마리로 구성한다. 5층마다 `별무리 광맥룡` 보스 1마리와 폐광 전용 호위 2마리를 배치한다. 적 ID와 아트 참조는 스테이지 몬스터 카탈로그와 분리한다.
- 한 라운드는 영웅이 살아 있는 적 중 가장 앞선 적을 공격한 뒤, 파티가 남아 있으면 다음 반격 순번의 생존 적 1마리가 공격한다. 순번은 고정·결정적이며 쓰러진 적은 건너뛴다. 복수 적이 한 라운드에 모두 공격하지 않도록 하여 기존 영웅 생존 밸런스의 급격한 붕괴를 막는다.
- 영웅의 적 공격은 현재 타깃의 HP를 0으로 만들면 즉시 처치 처리하고, 남은 적이 있으면 다음 라운드에도 첫 생존 적을 타깃으로 삼는다. 모든 적을 처치해야 층 승리이며, 영웅 HP가 0이 되면 즉시 패배한다.
- 한 층 도전은 현재처럼 최대 HP의 영웅으로 시작한다. 실패한 파티의 HP는 재시도에 이월하지 않으며, 재도전은 같은 층의 전체 적 파티를 초기 상태로 시작한다. 보상·`dungeon_cleared` 성공 행동은 파티 전원 처치 후 한 번만 생성한다.
- 적별 처치 수는 전투 로그·화면 표시용이다. 별도 이벤트 행동 카탈로그를 추가하기 전에는 적 처치마다 미션 진척이나 보상을 만들지 않는다. 이벤트 특별 던전의 적 수와 전투 방식은 승인된 템플릿 계약에 남겨 둔다.

WP-08에서 스테이지·일반 던전·특별 던전의 성공/실패를 서버 HP 전투로 판정한다. 각 유효 도전은 영웅 최대 HP에서 시작하고 영웅 선공, 생존 몬스터 반격 순서로 진행한다. 공격력에서 방어력을 뺀 값을 피해로 적용하며 최소 피해는 1이다. 대상 HP는 0으로 제한하고 HP가 0이 되는 타격 직후 전투를 끝낸다. 승리한 콘텐츠만 경험치·보상을 지급하고 성공 ActionRecord와 미션 진척을 만든다. 패배는 Attempt와 전투 로그를 저장하며 보상·성공 행동을 만들지 않는다.

| 명령 | 사전조건 | 성공 시 상태 변화 | 실패/거절 시 상태 변화 |
|---|---|---|---|
| stage_challenge | push는 최고 클리어 + 1, farm은 최고 클리어(미클리어 시 1), 해금 레벨 충족 | HP 전투 승리, XP/보상, 최고 클리어 갱신. push면 다음 스테이지를 반환 | 전투 패배면 Attempt만 저장. push 패배는 farm으로 전환하고 최고 클리어로 복귀 |
| dungeon_challenge | push는 최고 클리어 층 + 1, farm은 최고 클리어 층(미클리어 시 1), 해금 조건 충족 | HP 전투 승리, XP/보상, 최고 층 갱신 | 전투 패배는 Attempt만 저장. push 패배는 farm으로 전환해 최고 클리어 층으로 복귀 |
| special_dungeon_challenge | 활성 이벤트·유저 자격·현재 층·entry_level·시도권 충족 | HP 전투 승리, 층 전진, XP/보상 및 특별 던전 ActionRecord | 전투 패배는 같은 층 재도전 가능, 성공 행동·미션·보상 없음 |
특별 던전 카탈로그에는 층별 고정 `monster_count`를 둔다. `monster_kill` 기획 미션은 활성 이벤트의 특별 던전 층이 성공한 경우에만 `special_dungeon_progressed(progress_type=floor_cleared)` ActionRecord의 `monster_count`만큼 진행된다. Runtime은 목표치를 넘지 않게 값을 제한한다. 이 매핑은 `tinyheroes-1.0.0` source catalog용 허용 매핑이며, Action/콘텐츠 규칙 version이 다르면 적용을 거절한다.

콘텐츠 보상·경험치는 유한 템플릿에서는 카탈로그 값, 무한 stage/floor에서는 버전이 고정된 progression profile 계산값을 사용한다. 성공 보상은 인벤토리/재화 상태와 원장에 반영한다. 성공하지 않은 도전은 성장·미션·보상에 영향을 주지 않는다.

## 판정 순서

1. 인증 주체에서 유저를 확인하고 요청 ID·명령 타입·콘텐츠 참조를 검증한다.
2. 같은 요청 ID가 이미 처리되었으면 저장한 최초 결과를 그대로 반환한다. 같은 ID에 다른 내용이면 충돌로 끝낸다.
3. 해당 요청에서 사용할 단일 규칙 세트와 카탈로그 스냅샷을 고정한다.
4. 이벤트 기간·참여 자격·콘텐츠 해금·입장 레벨·콘텐츠별 한도를 확인한다. 일반 던전은 무제한 도전하며, 이벤트 특별 던전 등 제한이 있는 콘텐츠만 해당 한도를 적용한다.
5. 서버가 카탈로그 스탯으로 HP 전투를 계산하고 순서가 고정된 combat_log와 최종 HP를 확정한다.
6. 성공이면 성공 행동 기록(`ActionRecord`)을 만들고 카탈로그에 정해진 경험치와 진행 상태를 적용한다. 실패면 실패한 `ActionAttempt`만 남기며 성장·미션·보상은 변경하지 않는다.
7. 성공 `ActionRecord`를 고정된 Runtime 이벤트의 미션 필터와 집계 규칙에 평가한다. 같은 행동 ID는 미션별 한 번만 집계한다.
8. 미션이 처음 완료되면 보상 정의를 유저의 가상 보유 상태에 반영하고 `RewardRecord`를 함께 생성한다. 완료 표시와 지급은 한 번만 발생한다.
9. 유저 상태·시도/행동 기록·미션·보상·요청 결과를 하나의 논리 처리로 확정하고 결과를 반환한다.

일부 단계만 확정되어 나머지가 실패하는 경우는 허용하지 않는다. 구체적인 트랜잭션/재조정 전략은 저장소 및 Runtime 설계서가 결정한다.

## 행동 규칙

요청 명령과 판정 사실을 구분한다. 명령은 `stage_challenge`, `dungeon_challenge`, `special_dungeon_challenge` 중 하나이며, 성공 사실은 상위 문서의 `stage_cleared`, `dungeon_cleared`, `special_dungeon_progressed`로 기록한다. `growth_milestone_reached`는 성공 행동에서 경험치를 적용한 뒤 임계치를 넘었을 때 파생한다. 실패한 유효 도전은 `ActionAttempt(result=failed)`로 보존하지만 `ActionRecord`를 만들지 않고 미션 집계에도 넣지 않는다. 문법 오류, 인증 거절, 잠금/기간/자격 불충족은 유효 도전 전 도메인 거절로 기록한다. 일반 던전 연속 진행에는 일일 시도권을 적용하지 않는다.

행동 요청은 명령과 판정 결과를 분리한다. 클라이언트는 행동 종류·콘텐츠·요청 식별자와 허용된 선택지만 보낸다. Runtime은 인증 주체에서 유저를 결정하고 사용자·이벤트 자격, 콘텐츠 해금, 시도권, 게임 데이터/규칙 버전을 확인해 결과·보상·행동 기록을 생성한다. 성공 기록은 적어도 `action_id`, `request_id`, `user_id`, `action_type`, `content_id`, `runtime_event_id`(해당 시), `result`, `reason_code`, 서버 `occurred_at`, `game_ruleset_version`, `game_data_snapshot_id`를 보유한다. 사용자 입력 시각이나 결과/보상량을 판정 근거로 신뢰하지 않는다.

동일 행동이 여러 레벨 임계치를 통과시키면 원 행동과 임계치 ID 쌍으로 안정적인 파생 기록을 식별한다. 행동 기록을 미션에 집계할 때도 원 `action_id`를 근거로 보존해 재계산과 중복 배제를 가능하게 한다.

## 상태 및 기간 규칙

- 이벤트는 `scheduled → active → ended`로 진행한다. 종료 시각은 `[start_at, end_at)` 경계로 판단한다.
- 한 플레이 명령에는 최대 하나의 `runtime_event_id`를 연결한다. 이벤트 ID를 보내면 자격을 검사해 해당 이벤트만 미션 집계 대상으로 삼고, 생략하면 일반 플레이로 기록하며 이벤트 진행에는 반영하지 않는다. 동일 행동을 여러 이벤트에 자동 동시 집계하지 않는다.
- 일일 시도권이 있는 이벤트 특별 던전은 `Asia/Seoul` 시간대, 매일 00:00:00 초기화를 사용한다. 일반 던전은 무제한 진행하므로 일일 시도권을 두지 않는다. 규칙 세트에 제한 프로필을 명시하고 서버 호스트 시간대는 사용하지 않는다.
- 기간 비교와 원장 기록 시각은 UTC로 통일한다. 명령 판정 시 서버가 고정한 판정 시각을 사용하며, 같은 원자 처리 안에서 이벤트 활성 여부와 행동 발생 구간을 함께 평가한다. 제한이 있는 콘텐츠만 판정 시각을 규칙 세트의 `Asia/Seoul` 게임 일 경계로 변환한다.
- 유저의 이벤트 자격은 첫 참여 시점에 스냅샷으로 고정한다. 이후 세그먼트 규칙이 바뀌어도 기존 참여의 자격을 소급 변경하지 않는다.
- 기획 결과의 Day는 서울 시간대 이벤트 일차다. 행동은 해당 Day 미션에만 집계되며 이전 Day 미완료 미션은 `missed`, 이후 Day 미션은 `upcoming`으로 조회된다.
- 이벤트 종료 후 새 행동과 보상 변경은 거절한다. 조회는 허용한다.
- 특별 던전은 유저별 현재 진행 층만 도전할 수 있다. 실패하면 같은 층을 다시 도전할 수 있고 성공하면 다음 층으로 한 번 진행한다. 성공한 층을 반복 완료해 미션 횟수나 보상을 파밍할 수 없으며, 보스 층 성공으로 던전을 완료 처리한다. 일반 층 성공은 `progress_type=floor_cleared` ActionRecord를 만든다. 보스 층 성공은 동일 Attempt에서 `floor_cleared`와 `boss_defeated` 두 ActionRecord를 안정 ID(Attempt ID + progress type)로 각각 파생해, 층 도달 미션과 보스 처치 미션을 모두 판정할 수 있게 한다.

## 완료 기준

- 각 플레이 루프에서 입력, 권위 판정, 행동 기록, 이벤트 반영의 연결을 설명할 수 있다.
- 지원 행동별 성공·실패·중복 사례가 정의된다.
- 주요 이벤트 유형의 목표가 실제 게임 행동으로 달성 가능한지 재현할 수 있다.
