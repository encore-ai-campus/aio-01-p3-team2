# 게임 규칙·플레이 루프 설계서

## 문서 상태와 범위

- 상태: 논리 규칙 계약 정리 완료, 밸런스 fixture 수치 미확정
- 목적: 모바일 방치형 RPG 데모의 플레이 규칙과 이벤트 미션 근거가 되는 행동을 정의한다.
- 상위 기준: [가상 게임 도메인 상세 설계서](../가상게임_도메인_상세설계서.md) §§3–5, 7–9
- 다음 연결: [데이터·스키마](02_게임데이터_스키마.md), [검증·밸런스](07_게임검증_밸런스.md)
- 제외: 구체 밸런스 수치, 물리 저장/API, 에이전트 워크플로우

## 설계 원칙

1. 플레이 판정의 권위는 게임 Runtime에 둔다. 프론트엔드는 입력과 결과 표현을 담당한다.
2. 이벤트 기획은 허용된 게임 기능을 선택·설정하며 임의 코드를 추가하지 않는다.
3. 같은 게임 상태와 같은 행동 입력은 같은 결과를 내야 한다.
4. 임의 보상·경험치 지급은 허용하지 않고 버전이 지정된 규칙 데이터만 사용한다.

## 최소 플레이 루프

`로비 → 스테이지/일반 던전/이벤트 특별 던전 선택 → 입장 조건 판정 → 행동 결과 계산 → 행동 기록 생성 → 성장·이벤트 미션 반영 → 보상 기록 조회`

| 콘텐츠 | 규칙 책임 | 이벤트 근거 행동 |
|---|---|---|
| 스테이지 | 해금 순서와 권장 레벨을 확인하고 성공/실패를 판정한다. | `stage_cleared` |
| 일반 던전 | 던전·난이도별 입장 레벨, 일일 시도 한도, 성공 조건을 판정한다. | `dungeon_cleared` |
| 이벤트 특별 던전 | 활성 이벤트 및 등록된 템플릿 설정이 있을 때만 입장시킨다. 층/보스 완료를 판정한다. | `special_dungeon_progressed` |
| 성장 | 허용 행동의 경험치 보상과 누적 경험치 임계치를 적용한다. | `growth_milestone_reached` |

전투는 시연에 필요한 단순 결정 규칙으로 구현한다. MVP에서 성공 여부는 서버의 유저 레벨과 콘텐츠 `clear_level`을 비교해 계산한다. 연출용 랜덤은 결과가 확정된 뒤 표현에만 사용하고 미션·보상 판정에 영향을 주지 않는다. 난이도별 `clear_level`과 경험치·보상 수량은 데이터 fixture에서 정한다.

### MVP 판정 기준안

시연용 전투는 실시간 액션 시뮬레이션이 아니라 **서버가 콘텐츠별 `clear_level`과 유저 레벨을 비교해 성공/실패를 판정하는 결정적 도전**으로 정의한다. 입력 상태, 콘텐츠 데이터 버전, 규칙 버전이 같으면 결과가 같아야 한다. 화면은 준비·공격·결과 애니메이션으로 전투 감각을 만들 수 있지만, 애니메이션 프레임이나 클라이언트 난수는 판정에 관여하지 않는다. 이 기준은 전투 구현 범위를 작게 유지하면서 이벤트 미션의 실제 상태 변화를 검증하기 위한 MVP 권장안이다. 전투력·속도·적 행동 등 추가 요소는 규칙·fixture·검증 기준을 함께 정의할 때만 추가한다.

| 명령 | 사전조건 | 성공 시 상태 변화 | 실패/거절 시 상태 변화 |
|---|---|---|---|
| `stage_challenge` | 다음 미개방 스테이지는 직전 클리어와 `unlock_level` 충족; 이미 연 스테이지는 재도전 가능 | 시도권 없음; `level >= clear_level`이면 성공 사실·카탈로그 XP/보상 반영, 최고 스테이지 갱신 | 레벨 미달은 Attempt만 기록; 해금 불충족은 기록/변경 없음 |
| `dungeon_challenge` | `entry_level` 및 일일 시도권 충족 | 시도권 1 차감; `level >= clear_level`이면 성공 사실·카탈로그 XP/보상 반영 | 레벨 미달은 시도권 차감과 실패 Attempt; 한도/입장 불충족은 변경 없음 |
| `special_dungeon_challenge` | 이벤트 active·유저 자격·현재 층·entry_level·시도권 충족 | 시도권 1 차감; 성공 시 층 전진, XP/정의된 보상 및 성공 행동 생성; 보스면 던전 완료 | 레벨 미달은 시도권 차감과 실패 Attempt; 다른 층/이벤트 상태/자격/한도 불충족은 변경 없음 |

모든 콘텐츠 보상·경험치는 고정 카탈로그 값을 사용한다. 콘텐츠 성공 보상은 인벤토리/재화 상태와 보상 원장에 반영한다. 성공하지 않은 도전은 성장·미션·보상에 영향을 주지 않는다.

## 판정 순서

1. 인증 주체에서 유저를 확인하고 요청 ID·명령 타입·콘텐츠 참조를 검증한다.
2. 같은 요청 ID가 이미 처리되었으면 저장한 최초 결과를 그대로 반환한다. 같은 ID에 다른 내용이면 충돌로 끝낸다.
3. 해당 요청에서 사용할 단일 규칙 세트와 카탈로그 스냅샷을 고정한다.
4. 이벤트 기간·참여 자격·콘텐츠 해금·입장 레벨·일일 시도 한도를 확인한다. 도전 시도가 유효해 소비 단계에 도달하면 시도권을 먼저 1회 소비하고 `ActionAttempt`를 만든다.
5. 서버가 MVP 판정 규칙으로 도전 결과를 계산한다. `clear_level` 이상이면 성공, 미만이면 실패한다.
6. 성공이면 성공 행동 기록(`ActionRecord`)을 만들고 카탈로그에 정해진 경험치와 진행 상태를 적용한다. 실패면 실패한 `ActionAttempt`만 남기며 성장·미션·보상은 변경하지 않는다.
7. 성공 `ActionRecord`를 고정된 Runtime 이벤트의 미션 필터와 집계 규칙에 평가한다. 같은 행동 ID는 미션별 한 번만 집계한다.
8. 미션이 처음 완료되면 보상 정의를 유저의 가상 보유 상태에 반영하고 `RewardRecord`를 함께 생성한다. 완료 표시와 지급은 한 번만 발생한다.
9. 유저 상태·시도권·시도/행동 기록·미션·보상·요청 결과를 하나의 논리 처리로 확정하고 결과를 반환한다.

일부 단계만 확정되어 나머지가 실패하는 경우는 허용하지 않는다. 구체적인 트랜잭션/재조정 전략은 저장소 및 Runtime 설계서가 결정한다.

## 행동 규칙

요청 명령과 판정 사실을 구분한다. 명령은 `stage_challenge`, `dungeon_challenge`, `special_dungeon_challenge` 중 하나이며, 성공 사실은 상위 문서의 `stage_cleared`, `dungeon_cleared`, `special_dungeon_progressed`로 기록한다. `growth_milestone_reached`는 성공 행동에서 경험치를 적용한 뒤 임계치를 넘었을 때 파생한다. 실패한 유효 도전은 `ActionAttempt(result=failed)`로 보존하지만 `ActionRecord`를 만들지 않고 미션 집계에도 넣지 않는다. 문법 오류, 인증 거절, 잠금/기간/자격 불충족은 소비 가능한 도전 시도가 아니므로 시도권을 차감하지 않는다. 시도권을 소비한 뒤 계산된 실패는 시도권을 돌려주지 않는다.

행동 요청은 명령과 판정 결과를 분리한다. 클라이언트는 행동 종류·콘텐츠·요청 식별자와 허용된 선택지만 보낸다. Runtime은 인증 주체에서 유저를 결정하고 사용자·이벤트 자격, 콘텐츠 해금, 시도권, 게임 데이터/규칙 버전을 확인해 결과·보상·행동 기록을 생성한다. 성공 기록은 적어도 `action_id`, `request_id`, `user_id`, `action_type`, `content_id`, `runtime_event_id`(해당 시), `result`, `reason_code`, 서버 `occurred_at`, `game_ruleset_version`, `game_data_snapshot_id`를 보유한다. 사용자 입력 시각이나 결과/보상량을 판정 근거로 신뢰하지 않는다.

동일 행동이 여러 레벨 임계치를 통과시키면 원 행동과 임계치 ID 쌍으로 안정적인 파생 기록을 식별한다. 행동 기록을 미션에 집계할 때도 원 `action_id`를 근거로 보존해 재계산과 중복 배제를 가능하게 한다.

## 상태 및 기간 규칙

- 이벤트는 `scheduled → active → ended`로 진행한다. 종료 시각은 `[start_at, end_at)` 경계로 판단한다.
- 한 플레이 명령에는 최대 하나의 `runtime_event_id`를 연결한다. 이벤트 ID를 보내면 자격을 검사해 해당 이벤트만 미션 집계 대상으로 삼고, 생략하면 일반 플레이로 기록하며 이벤트 진행에는 반영하지 않는다. 동일 행동을 여러 이벤트에 자동 동시 집계하지 않는다.
- MVP 데모 게임의 일일 시도권 기준은 `Asia/Seoul` 시간대, 매일 00:00:00 초기화로 둔다. 규칙 세트에 이 값을 명시하고, 서버 호스트 시간대는 사용하지 않는다.
- 기간 비교와 원장 기록 시각은 UTC로 통일한다. 명령 판정 시 서버가 고정한 판정 시각을 사용하며, 같은 원자 처리 안에서 이벤트 활성 여부와 행동 발생 구간을 함께 평가한다. 일일 시도권은 판정 시각을 규칙 세트의 `Asia/Seoul` 게임 일 경계로 변환한다.
- 유저의 이벤트 자격은 첫 참여 시점에 스냅샷으로 고정한다. 이후 세그먼트 규칙이 바뀌어도 기존 참여의 자격을 소급 변경하지 않는다.
- 이벤트 종료 후 새 행동과 보상 변경은 거절한다. 조회는 허용한다.
- 특별 던전은 유저별 현재 진행 층만 도전할 수 있다. 실패하면 같은 층을 다시 도전할 수 있고 성공하면 다음 층으로 한 번 진행한다. 성공한 층을 반복 완료해 미션 횟수나 보상을 파밍할 수 없으며, 보스 층 성공으로 던전을 완료 처리한다. 일반 층 성공은 `progress_type=floor_cleared` ActionRecord를 만든다. 보스 층 성공은 동일 Attempt에서 `floor_cleared`와 `boss_defeated` 두 ActionRecord를 안정 ID(Attempt ID + progress type)로 각각 파생해, 층 도달 미션과 보스 처치 미션을 모두 판정할 수 있게 한다.

## 결정·미결

| 항목 | 상태 | 다음 결정 위치 |
|---|---|---|
| 콘텐츠별 입장·클리어 판정 | `entry_level`/해금 조건 및 `clear_level` 비교 계약 확정, 실제 수치 미정 | 데이터·스키마 및 검증·밸런스 fixture |
| 전투 실패 조건 | 유효 도전 중 `user_level < clear_level`이면 실패 | ruleset과 fixture 수치 확정 |
| 일일 시도 초기화 시간대 | MVP 기본값 `Asia/Seoul`, 00:00:00 | ruleset 데이터에 버전 고정 |
| 전투 판정 | `clear_level` 기반 결정적 비교를 MVP 기준으로 명시 | 수치 fixture 검토 후 ruleset 버전 고정 |
| 전투 난수 | MVP 권위 판정에서 사용하지 않음; 연출 난수는 결과에 영향 없음 | 향후 추가 시 seed·규칙 버전 기록 및 재현 계약 필요 |
| 실제 전투 수치·성장 곡선 | `clear_level` 결정 판정, 수치 fixture 미정 | 검증·밸런스 fixture 확정 |
| 행동/성장/미션/보상 변경의 원자성 | 한 논리 처리 단위로 정의, 물리 구현 미정 | 저장소·DB, Runtime/API |

## 완료 기준

- 각 플레이 루프에서 입력, 권위 판정, 행동 기록, 이벤트 반영의 연결을 설명할 수 있다.
- 지원 행동별 성공·실패·중복 사례가 정의된다.
- 주요 이벤트 유형의 목표가 실제 게임 행동으로 달성 가능한지 재현할 수 있다.
