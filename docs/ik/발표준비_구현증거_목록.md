# 발표 준비: 구현 증거 목록

기준일: 2026-10-13 (Asia/Seoul)

목적: 발표 필수 산출물 3종에 넣을 수 있는 **이미 구현된 재료와 기존 검증 증거**를 정리한다. 새 코드를 작성하거나 새 환경에서 시험한 결과로 간주하지 않는다.

## 증거를 읽는 기준

| 상태 | 뜻 | 발표에서의 사용 |
|---|---|---|
| 코드 확인 | 저장소 코드·설정에서 구조와 계약을 확인 | “코드에 구현되어 있다”라고 설명. 실행 성공의 근거로 쓰지 않음 |
| 기존 실행 증거 | 보고서에 보존된 특정 커밋·환경·모집단의 실행 결과 | 해당 실행 범위와 시점을 같이 밝히고 사용 |
| 현행 환경 확인 필요 | 새 배포 환경이나 최신 변경에서 실행하지 않음 | 완료·수용·운영 중이라고 주장하지 않음 |
| 계획/미구현 | 문서상 설계나 후속 작업만 존재 | 계획 또는 한계로만 소개 |

최신 [Actions 전체 경로 AWS 검증](검증산출물/2026-10-13_Actions_전체경로_AWS_검증.md)에서 hosted first/update/reset을 실제로 완료했다. 현재는 AWS ABSENT 및 17개 분류 잔존 0이며 IAM/OIDC만 유지한다. 이전 ACTIVE 표시는 당시 이력이다. 제출 기준은 [필수 산출물 대문](필수산출물_README.md)을 따른다.

기능 시험 source는 e476376, 전송 보완 source는 530fd03이다. 최신 보완 CI 38334819091에서 731 PASS와 동일 SHA/run/attempt JUnit hash를 확인했다. 배포와 시험은 source별로 기록하며 현재 working tree의 다른 문서 작업을 기능 시험 source로 주장하지 않는다.

## 발표 전 증거 보강 순서

1. 기준 상태/source/run은 최신 전체 경로로 동기화했다. 팀 실명·담당·기간 표지는 팀에서 확인한다.
2. 공개 문서·증거와 보호 원문/키를 분리한다. 최신 CI source 530fd03/731 PASS를 이전 707 PASS와 합치지 않는다.
3. 각 보고서의 숫자를 원본 결과에서 다시 대조해 모집단·환경·커밋·실행 ID를 함께 적는다.
4. 로컬 정상 흐름과 대표 복구 흐름을 촬영하고, 실행 중인 화면이 아니면 녹화/정지 이미지임을 표시한다.
5. hosted 배포 수용은 완료됐다. 알림 수신은 미검증이며, 발표 영상·슬라이드는 별도 제작해야 한다.
